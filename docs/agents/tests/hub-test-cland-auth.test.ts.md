# hub/test/cland-auth.test.ts

T3 executes a copy of `hub/src/host/cland-auth.sh` in a disposable root through `/bin/bash`. All external commands, including mount, umount, fsfreeze, process discovery and signals, are stubs in that root. The child environment is sealed by `fixtureEnvironment`; PATH contains only the stubs. Never use sudo or a real mount to run this test.

Run `node --test hub/test/cland-auth.test.ts` with supported Node 24 and inherited `CLAND_*` removed. This lightweight stub-script file needs no heavy native preservation slot. QA repeats it on the integrated stage head. Assertions check native exit receipts, refusal without external commands, freeze/thaw dispatch for a matching volume, wrong-volume refusal, writer drainage before unmount and refusal when writers persist. Each child has a `testWaitMs()` diagnostic timeout and is synchronously reaped before its scratch root is removed. Stubbed sleeps do not measure the production wait duration. No browser or provider API is used.

C1/C2/C3 rendering checks live in `hub/test/host-prelude.test.ts`. Real device appearance, ext4 mount behavior and real fuser semantics are not exercised here.

The fixture redirects only the root-owned operation-lock pathname into its scratch root and stubs flock as well. Lock contention is a stubbed refusal control, not a native flock timing claim. Mount receipts include ID and source; disappearance, replacement with another volume and replacement with the same source under a new ID are refused. Error controls cover fuser statuses 1 with diagnostic, 2 and 127 plus an actually missing command. A positive lock-file census precedes every no-user census; failures keep the disk fenced. A disabled-freshness mutation was observed red before retaining the mount-change regression.

The valid-mount control additionally redirects the device-directory constant to a scratch directory containing an ordinary fixture file; mount, mountpoint, ownership and permission commands remain stubs. No production path override is exposed. The writer census uses psmisc's [silent-mode exit contract](https://manpages.debian.org/bookworm/psmisc/fuser.1.en.html), with an independent positive control and diagnostic checks because nonzero alone also covers fatal errors. The committed C-216 allowance expires 2026-11-13 and names the observed macOS samples; it is duration evidence only, not product latency or Linux coverage.

A late-change control replaces the admitted mount ID after the completed writer census and proves both the signal path and the final unmount path refuse their effect. Native flock concurrency itself remains unmeasured; the stub contention control proves fail-closed handling of its admission receipt.
