# hub/test/cli-usage-merge.test.ts

Edit command help in its owning `hub/src/cli/usage/<command>.ts` module. `usage.ts` is the compatibility facade: it re-exports the existing constants and composes the legacy init/update, publish/release/sync and subscribe/unsubscribe/subscriptions blocks. `usage/task-import.ts` owns `IMPORT_USAGE`, imported by the task module. Keep these modules free of command implementations.

The T1 command-help table covers every advertised command in process. T2 keeps five real CLI help launches; see [CLI help coverage](hub-test-cli-help.test.ts.md). Help bytes and public export composition stay unchanged through this split. The source import graph now includes 36 pure command-help modules; `cli-imports.test.ts` asserts that count separately from the existing implementation budgets.

The T3 test copies the owning command modules into a disposable Git repository, commits independent verify/executor and init/update edits, and checks native `merge-tree` and `merge`. Git runs synchronously with the shared sealed fixture environment and `gc.auto=0`; no writer remains at cleanup. No union merge attribute is needed for command modules.

The T1 `cli-usage-compatibility.test.ts` freezes every named export; T2 `cli-help.test.ts` checks actual `cland --help` bytes in a sealed disposable cwd. Their fixtures were captured before this refactor. The full-help fixture stores the original block order and surrounding bytes using named placeholders, expanded only from the frozen export data (never from production exports). Frozen command rows in `commands.json` also retain blank separators, so future independent help edits do not conflict in a second golden-output file. The frozen `exports.json` stores only the original export composition, while `commands.json` owns the command bytes. Deliberate help changes update only the owning frozen command row; ordering or surrounding text changes update the full-help template. Only the version header follows the current version. Existing help-byte guards remain unchanged; the import guard separately counts pure help modules and retains the implementation budgets.
