# hub/test/host-revoke.test.ts

T2 proves that Sessions stops all three harness owners on their placed fake Host,
settles simulated native/file receipts before the cut and refuses subsequent
Host calls and new launch admission. This in-memory adapter test complements
host-settlement's release/forget and held-receipt unit cases; it does not run
native harness binaries.

Held-boundary controls rename/reuse a later display name during an earlier stop
and keep a pre-existing failed-launch producer held through a fake-clock
revocation deadline. The durable captured generation stays the authority, and
its pending-stop receipt remains reported until positively cleared.

Production OpenCode adapter controls use a recording Host and mocked native RPC,
normal stop, retained real config/password files, row prune or legacy-row state,
and a storage reopen before revocation. Files then disappear without another
native stop. Retirement receipts carry no recovered process signal authority.

Normal-exit variants drive the production OpenCode polling/settlement owner to
the durable exited row before restart/prune. A positive closure callback keeps
retirement ownership; a legacy terminal row without that receipt stays named as
incomplete and its private files remain. Neither recovered path signals a PID.

Both explicit-stop and normal-exit matrices include archived/pruned display rows,
legacy rows without the new receipt, and legacy rows archived/pruned before
restart. Unknown legacy closure is preserved and reported; no new signal is
issued. The positive terminal callback is persisted before the exited row.

The matrix also retains an older unknown native generation of the same stable
session, and untracked private-file locations. They remain named and untouched.
Separate storage controls cover generation-specific clear, prior stable-session
receipt compatibility and normalization. Private file-name policy comes from
the production server-files owner, shared with retirement cleanup.

An untracked agent admission directory is reported by its launch id with zero
signals. The path uses the agent owner's AGENT_LAUNCH_DIRECTORY constant. This
observation never restores native authority from file contents or saved flags.


Changed-boot component controls cover Claude, Codex and OpenCode, with accepted
rows, pending native cleanup and pending file undo. They preserve real private
files outside the run folder, reopen storage, advance retry time and revoke.
No adapter stop, native observation or agent adoption runs. Confirmed closure
keeps unresolved resource retirement named; pending ownership is never dropped.
Negative controls reject same/malformed boot proof and foreign/replaced owners,
fence an admitted continuation and a captured Host, and retain distinct Claude
generations of one stable session.


A post-retirement regression completes metadata deletion and durable resource
receipt clearance, holds later inventory before the authority cut, and checks
all five captured native operations. The fence survives the cut, storage reopen
and native-row replacement; a new-birth positive control reaches the fake native
boundary. The matrix covers new independent fences and prior resource-row-only
markers, preserved lazily before cleanup with no history scan.


The OpenCode stop/exit matrix includes an ancestor alias through prune/restart:
launch-captured canonical directory and device/inode ownership authorise metadata
retirement. Retargeted aliases, final directory symlinks and same-path inode
replacement stay named and preserve private files. Symlinked inventory remains
explicitly unknown. These are component checks without native harness children.
