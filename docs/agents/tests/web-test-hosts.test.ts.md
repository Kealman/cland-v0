# web/test/hosts.test.ts

`Sessions Hosts consumes the fake provider inventory snapshot and configuration push` acquires two directory-only fake-provider machines, supplies test Hosts (no SSH), and uses the production hub projection unchanged. It checks the rendered snapshot counts and a hot `max_hosts` update, including `applies: now`, using FakeClock and both fake lock process tables. Its fake registry supplies tunnel observations at the same subscription boundary as a carrier. Production HostHealth, HostsState coalescing, socket publication and the browser remain in the loss/recovery path. The observer is armed before loss with an exact one-second real-time bound; the hub clock advances through the full 1000 ms coalescing window. Recovery must render the plain pool again. Fake machine directories have disposal owners.

`web/test/hosts.test.ts` runs at Web with a disposable projectHub and isolated Chrome Headless Shell. The scripted cases replace the existing safe `hosts.state` and optional Sessions snapshot projection at the browser socket edge with fake pool facts. Those cases measure push-to-render; the production-backed case above includes health and coalescing. Nothing uses a real provider, SSH or credential. The injectable daemon `createHostRegistry` dependency defaults to the existing registry; only this fake overrides it.

`Sessions Hosts renders pushed facts and alert recovery (desktop)` and the corresponding `(phone)` case check host/slot/login counts, the Claude short label, signed-out counts, folding, every host detail, unknown prices, locally advancing uptime with unchanged pushed spend, outage red within an exact second, provider failure red, and plain recovery. The 320-pixel phone case checks page and row overflow. The existing Fold dispatch owns the controls; no binding or listener is added.

`Sessions hides Hosts for an empty pool list and a previous hub snapshot` checks no-pool hiding and the previous wire shape with neither the optional snapshot field nor host pushes. The populated cases also check that the client never requests `host.status`.

The desktop and phone pushed-facts cases share a FakeClock initialized from the run's current time with the hub and use `pausePageClock` before navigation, so the page clock owns the uptime interval from its creation. After the host row renders, advance the hub clock and `page.clock.fastForward(2000)`, then observe the exact `1h 0m 2s` rendered uptime and retain the changed-text and unchanged-spend assertions. The DOM wait bounds rendering after clock advancement; it does not wait for two seconds of real time. To prove sensitivity in a disposable source copy, slow only HostsView's uptime interval from 1000 to 60000 ms: both cases must fail with `uptime advances without a push`. Restore it before five sequential lone file runs. No GUI browser or real provider participates.

The file owns `ensureWebBuild` in its before hook, rebuilding stale or missing candidate output for isolated invocation as well as accepting a current runner build receipt. For a targeted run, select supported Node, strip inherited CLAND variables, then run `node --test web/test/hosts.test.ts`. Every pre-armed asynchronous observer is joined in a finally block before page disposal, including when its trigger fails. Browser group and hub shutdown receipts are emitted by the shared fixture. Stage QA runs on dev under the epic brief. The optional registry dependency preserves the default native path; no native lifecycle behaviour is changed.
