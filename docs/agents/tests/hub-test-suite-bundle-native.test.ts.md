# hub/test/suite-bundle-native.test.ts

Moving-root controls include periodic dev and integrated soak, stage, epic and
release occasions. Soak has one producer; the configured periodic and other
occasion plans have two. Each producer bundles/fetches the original commit after
root source HEAD advances, then supplies its own start/completion receipts.

T3 proves actual admitted commit bytes with disposable native Git. Each periodic
and soak callback uses `suiteCase` in native mode: register the whole-caller
normal/signal owner before acquisition, adopt the fixture root inside setup,
fence every asynchronous step, and join Git close and scheduler delivery before
fixture removal. `fixtureEnvironment` seals HOME, XDG, Git and credentials after
overlays. No real provider, droplet or browser is used.

Advance root source HEAD at delivery, dirty the later source, and bundle using
the scheduler's actual committed-only argument. Fetch into a scratch bare repo;
assert the original source bytes, run head and executor start/completion. Earlier
T2 receipts from suite-soak-component do not prove these migrated T3 identities.

The periodic fixture configures two shards with two classified inputs. Read the
admitted producer plan (`job.shards`, or the whole job for soak), keep a separate
bundle for every producer id, and share one in-flight root-advance operation.
Assert each bundle's captured commit and exact producer ref, receiver source,
temporary-ref deletion and producer start; finish every producer and observe the
parent's durable result. The soak control retains its single-producer contract.
Never substitute the parent id for a sharded producer's Git ref or worker id.

Item cases write an untracked log or edit tracked source in the fake host gate,
then fetch the delivered bundle into a disposable bare receiver and compare the
entire Git tree to the submitted tree. Exactly one gate and one bundle are
required. Moved-head cases commit after T0 or at executor delivery and require
the distinct `head moved` cause, zero completed bundles and zero remote starts.
Every case retains the shared whole-case owner; no wall-clock bound proves work.

The unchanged positive control retains the host T0 tree; dirty-input cases clear
the host tree and supply no submitted-tree T0 proof while keeping native exit 0.
Execute the production detached-check command in a checkout fetched from the
bundle: a durable file records remote execution for uncertain inputs or reuse
for unchanged inputs. This checks command execution, not an injected log label.

Uncertain nonzero host cases retain native exit 1 and run detached T0. Its native
shell exit (0 or 2) feeds the fake executor's final completion; assert that final
outcome independently from the saved host exit and host log. Known unchanged
failure and both unchanged/changed interruption controls refuse delivery with
zero bundles and zero remote starts. Existing success and moved-head assertions
remain in place.
