# hub/test/suite-admission-cost.test.ts

The T2 admission fixture sends real suite.start frames to an in-process hub.
Git object reads and process startup costs use an in-memory adapter and fake
clock. Native launch guards include callback and custom-promisified exec routes,
with positive controls. Provider acquisition and remote tree delivery are excluded
by dry-run; no provider or network probe runs.
The crew creates stageCase before acquisition. Setup and the whole callback have
separate observation bounds; each request continuation remains owned if a sibling
rejects. Candidate computations join independently of client deadlines. Hub close
and stopped receipts precede root cleanup and adapter/spy/native-guard restoration.

The recurring regression sends three concurrent admissions. Its duration manifest
uses the repository's duration titles, distributed over three test paths. Generated
sources register those titles through dynamic loops, so identity lint visits the
sources and records dynamic titles rather than searching thousands of literal
patterns per key. Timings are synthetic and allowances empty. This preserves
repository-scale metadata parsing without repeating repository-scale filesystem
traversal in every T2 run. The separate ten-request Linux measurement is retained
in A-23356, run 11274f5e: 27,719.6 ms for replies against the 90-second CLI wait;
the full case was 29.971 seconds and the overall run failed its duration budget.
The smaller fixture's timings must not be compared as a production speedup.
It asserts one YAML tokenization of the exact duration bytes across all requests.
Fresh JSON parsing, ownership checks and source identity validation still run.
Each request retains the CLI's 90-second reply wait. Measured crew wall times
are diagnostic evidence, not a separate timing gate. Phase diagnostics are overlapping
concurrent wall durations; they must not be summed as CPU time.
