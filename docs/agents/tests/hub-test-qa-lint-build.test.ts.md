# hub/test/qa-lint-build.test.ts

The T3 native-Git seam proves offline lint reads immutable source at HEAD or an explicitly selected old commit. Every Git and CLI child uses `fixtureEnvironment` after all options; the disposable repository owns HOME, XDG paths and Git configuration. The regression keeps a changed working tree before committing so a filesystem-based implementation fails its positive control. No hub or browser starts.

The production-install regression copies the candidate executable and source into a disposable install with no node_modules. It invokes the copied public CLI against a scratch committed test title. Its pre-fix control failed with `MODULE_NOT_FOUND: typescript`; the passing receipt must include the selected commit SHA. This deliberately proves the offline command has no parser/devDependency requirement without pruning or modifying the shared dependency install.

The committed-dev corpus case clones repository objects read-only into a scratch bare repository with fixtureEnvironment; it writes no project source or refs. It uses the dev ref when present, or explicitly labels detached candidate HEAD on prepared executors without that ref (that fallback is candidate evidence, not a dev receipt). It records the immutable source ref/SHA, brief count, findings, unresolved names and false file/title absences. Every committed qa/briefs Markdown file is linted. An independent TypeScript 5.9.3 literal-call AST oracle (test-only dev dependency) checks any reported absent title; Git tree membership checks absent files. Historical missing references and other findings are retained as drift, not a clean-brief claim. The earlier M4/M5 red matrix is the positive false-absence control; the final corpus must have zero false file/title absences.
