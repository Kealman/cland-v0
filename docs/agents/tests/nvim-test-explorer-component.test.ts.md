Four injected-small-limit controls cover per-page event and byte overflow and aggregate event and byte overflow across individually valid pages. Each changes an earlier-page row, observes the exact replacement first-page request, then asserts the fresh row, complete unique membership and released snapshot journals. The replay and active-page budgets share one traversal allowance (default 2,048 events / 2 MiB); overflow invalidates the entire traversal. Legacy snapshot users retain per-read retries.

The late-page control holds original first and later page replies across multiple retry rounds. It checks at most two pending attempts sharing one capture, releases the original late answers and asserts final complete unique membership plus the earlier-page row updated during later-page retries. Ordinary per-read retries remain unchanged; coherent paged retries count each pushed event once across both attempts.

The late-page refresh starts with already-loaded rows, so its completion receipt must be a new, un-emitted row carried only by the final page. Hold that exact reply, arm the marker-row observer before releasing it, then keep the final zero-journal and unique-id assertions.
