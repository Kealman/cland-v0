# QA brief: E-579 Hub hygiene, part 2

This brief is the Definition-of-done demo of epic E-579, the verify-queue hygiene stage carried over from E-425 (its former C1, C2 and the moved C2 of E-426). QA runs it in the human's place, at a named `dev` commit, on a droplet through the demo lease (decisions D16 and D19 of v0.1 §4). It has two parts and a read-only third.

- **Part D, the droplet.** One demo lease at the requested commit. On it: the build identity; the candidate-tree identity of a scratch repository across a tracker commit, a rulebook commit, a docs commit and a source commit (C1, C3); a scratch hub whose suite slot is held by a planted integrated cover, where a targeted test start is refused with `cover-quiet` and the cover's own worker, an unrelated project without a hub and the released slot are admitted (C2); and the children's own test files, one at a time (hub tests with a fake run, the proof the criteria name). The droplet is the isolated machine: the cover-quiet demo plants lock files that on the shared Mac would stop other sessions' tests, so nothing of it runs on the Mac.
- **Part L, local macOS.** None. No check here needs macOS, and none may touch the machine suite lock or run a suite on the shared Mac.
- **Part R, the live project, read-only.** The two children's items, their recorded evidence, the docs, and the rulebook path set.

Everything the run needs is in this file or in the files it names: whoever runs it cannot ask.

This brief is "part 2" of E-425 `qa/briefs/E-425.md` and reuses its structure and conventions (one lease, scratch identity stripped, no doctor on the Mac, counts and pids rather than command lines).

## Grants

none. The demo lease is not a grant: the hub gives its controls to QA holding the epic (G2). No tmux, no web terminal, no real harness session. The scratch hub on the droplet launches no session at all.

## Pitfalls

- **Identity.** QA's own commands (`cl`) act as QA on the live hub. Every scratch command on the droplet strips the `CLAND_*` variables, `CLAND_TEST_IGNORE_COVER` and `DIGITALOCEAN_TOKEN`. A scratch command that prints the live project's items, sessions or topics reached the live hub: stop, record that check BLOCKED, and do not repeat it.
- **Never retry a refusal another way.** A hub action refused to QA is recorded with its exact text and escalated to the requester; it is not repeated through another path or identity.
- **The planted cover is a lock file, not a suite.** The cover script's own process is the "cover"; it owns the owner file for the few seconds the script runs. Nothing on the Mac is locked. Do not copy `cover.mjs` to the Mac.
- **No doctor on the Mac**, and never `cland doctor --fix` anywhere in this brief.
- **Droplet exec quoting.** Commands are argument vectors: `bash -c '<script>'` with `$PWD`, `$T` and `$Q` inside the single quotes so the droplet's shell expands them. A quoting error that is not a product result is INCONCLUSIVE with the exact message, then fixed in a new command in the same lease.
- **The drafter did not run these commands.** S1 to S3 and D2 to D3 are written from `hub/src/verification-tree.ts`, `hub/src/test-admission.ts` and `cover()` in `hub/test/cover-quiet.test.ts`. If a module path or export name differs at `S`, report a brief defect and use the nearest equivalent; do not mark the product failed for it.
- **One lease.** Never run `demo start` twice. Record D lines before `demo stop`.
- **Never work around a refusal.** A refused demo control or verdict is evidence: record its exact text.
- `qa-record.sh` takes `E-579`. The verdict goes on `E-579`.

## Procedure

1. Choose a run id, `qa-<date>-<n>`, and set the Environment. Announce START in the request's topic, naming `S`. `dev` is not frozen: D8 decides.
2. Run, in order, recording each with `qa-record.sh` under `.cland/qa/E-579/<run>/` of the root:
   1. G0, G1 and G2. If any is not PASS, stop: the run is BLOCKED.
   2. Part D: D0, D1, then S1, then D2 to D7 one at a time on the one lease. Then D8, and D9 last of Part D.
   3. Part R: R1 to R5.
3. Fix nothing. A failure is a finding: write down the check id, the command and what it showed.
4. The verdict is `clear` only when every check in scope is PASS. Otherwise it is `not clear`, naming each check that was FAIL, BLOCKED or INCONCLUSIVE.
5. If a step fails, keep what is already written and finish from there. Never rerun a check under the same run id; a D4 to D7 rerun is the flaky rule's one rerun, in the same lease, reported beside the first result.
6. Before the verdict, run D8's freshness read again if `dev` moved since D8. Publish the evidence with `artifact.create` (kind `note`: the check table; the lease, executor, commit, lifetime and cost; which checks ran where; the findings) **in the epic's topic where the request was delivered**, and name its id in the verdict text.
7. Write one verdict on E-579 from `$W`: `cl task comment E-579 "<text>" --verdict qa --result clear --run $RUN --commit $S --verified all`. A not-clear verdict carries only `failed` (one `{ criterion, note }` per failed criterion, single-line notes) and names in its text the criteria that passed. The text opens with the check table, then the findings ranked high, medium and low. If the hub refuses the verdict as `qa-stale`, keep the evidence and report BLOCKED. Any other refusal: fix its cause and write only the verdict again with the same run.
8. Release the hold if the verdict did not: `cl task hold E-579 --release`. Remove the build worktree: `git -C $R worktree remove $W`.
9. Report with `send` kind `report` to `lead E-579` in the request's topic: first line `qa clear E-579` or `qa not clear E-579`, then the failed checks, the lease and its cost. Report any find outside the epic as a bug found aside, with its evidence.

## Lessons applied from earlier runs

- E-425: one lease; scratch commands strip QA's identity; process checks print counts and pids, never command lines; no doctor on the Mac; the machine suite lock is never touched.
- T-386 and E-423: no full suite; supporting test files one at a time on the droplet; a failure is rerun once and both results are reported.
- The cover-quiet rule itself: a planted cover never runs on the shared Mac.
- E-676: a check that rests on a decision or on a substitute says so in the verdict.
