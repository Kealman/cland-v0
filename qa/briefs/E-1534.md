# QA brief: E-1534 — Definition of done (Pools, placement and the scheduler)

This brief is the Definition-of-done demo of epic E-1534 (qa skill, "Epic demos on a named dev commit"). QA runs it in the human's place at a named `dev` commit and records one epic verdict that names, by id, the criteria it verified (C1–C8). Everything the run needs is in this file or in the files it names: whoever runs it cannot ask. Commands are for bash (start `bash` first; zsh reads `$S:q`, `$B:h` or `${B}:hub` as modifiers and does not split unquoted path lists; always brace a variable before `:`). **No real SSH, host, droplet provider call, DigitalOcean API, key, credential, npm registry or network (R-1530's QA rule):** every provider in this run is the fake host provider or the scripted fake DigitalOcean API inside a named test file.

**Working copy, drafted at `1dcf41442da2c0bd71ba70c9f9695533d823d497`** (the commit that closed stage 3's landings; stage-3 QA pending at writing). The Coordinator commits it and names the demo commit `S` in the request. Markers: VERIFIED = read at `1dcf4144`; INFERRED = a reasoned expectation no read or run has proven, never a pass condition on its own.

**Where it runs.** Two places, framed by gates and a freshness check; the case and manual tables name `droplet` or `local macOS` for every row:

- **Part D, the droplet.** One demo lease at `S` through `cland demo start|exec|status|stop E-1534` only (E1534D-02). In the delivered tree QA runs the named hub test files that carry C1–C8, one file at a time (E1534D-10 to E1534D-38), with every `CLAND_*` name stripped. Then it releases the lease (E1534D-39). **Fallback:** if start is refused for lack of a remote slot or spend budget, set `LOCAL=1`: every Part D row runs on this Mac in the clean worktree through the stage-3 seal after `quiet`, the native T3 files under the preservation lock, and the verdict names the refusal. Any other start failure is BLOCKED, reported to the requester.
- **Part L, local macOS.** The build, plan and hold gates (E1534D-00, E1534D-01), the typecheck (E1534D-04), the web build (E1534D-05), the three stage briefs' source checks re-run at `S` (E1534D-06) and the C6 refusal sweep (E1534D-07), the headless Neovim and web inbox files (E1534D-40, E1534D-41), and **one end-to-end scratch flow on a CLI-started hub with fake hosts** (E1534D-60 to E1534D-73): a pool configured in `[hosts.agents]` and an Implementer bound to it; `min_hosts` keeping a host; placement on that ready host; a waiting launch in `cland session list` and the inbox frame; `cland config set hosts.agents.max_hosts 2` scaling up without a restart; `cland host status`; idle stop of an emptied host; a hub restart while a fake host is deleted, so its session exits; `cland host list --json`; `cland host stop` with a live session; the Coordinator's local-only pool refusal and a live `spread` change; a host started on demand renewing its lease; the detached watchdog deleting it after the hub stops; the census. The flow reuses stage 3's scratch functions from `qa/briefs/E-1534-stage-3.md` at `K3` unchanged and adds four (`d69` to `d72`).

**What the scratch hub cannot drive, and what carries it.** A tunnel outage (T-1753: the tunnel state comes only from the SSH carrier, and its tests inject it), a boot or SSH-key failure (T-1750: the fake provider's `neverBoot` and `pinned-key` modes are test seams), the hosts sub-cap and its 80 % General line (T-1751: the fake provider's prices are zero, so no CLI spend reaches a cap), the memory floor (T-1741: no real memory pressure), and a DigitalOcean create (T-1756: the DigitalOcean provider needs a token, which the seal refuses, and the scripted fake API is a test fixture) are **component-only**: the named files on the droplet carry them (E1534D-14, E1534D-26 to E1534D-29, E1534D-32 and E1534D-34). No scratch row fakes them by hand.

The run is meant to take about five hours: gates, demo start and the droplet files about 150 minutes (one exec per file; the two native files wait out real host boots); the local inbox files and web build about 25 minutes; the scratch flow about 80 minutes (real host boots, a 2-minute lease cadence and a watchdog deadline). Waits for the demo lease, cover-quiet admission, the preservation lock or load are not product results.

## Item

- **Definition of done, verbatim from `task view E-1534 --json` at `1dcf4144` (VERIFIED):**
  - C1: Pools are configured in `[hosts.<pool>]`, hot-reloaded and scaled with `cland config set`, and roles bind to them with `[<role>.launch] pool`, the Coordinator and the Aide only `local`.
  - C2: Placement packs densely by harness weight within `slots`, spreads with `spread = true`, and the host agent refuses a launch below 1.3 GB free memory.
  - C3: A launch that cannot be placed waits as a status line with its current reason in both inboxes, Agents and `cland session list`, never as an ask, and is placed when room appears.
  - C4: Pools keep `min_hosts`, start hosts on demand up to `max_hosts`, stop an empty host after `idle_stop`, and never stop a host with sessions except by `cland host stop`.
  - C5: Each host has a lease renewed while it works, and its detached watchdog deletes it at the deadline with the hub stopped.
  - C6: Boot and SSH failures after 5 minutes, unreachable hosts after 3 and 15 minutes, provider API limits and destroyed hosts each behave as spec §3.6 says.
  - C7: Agent hosts book under the ledger's `hosts` category, the sub-cap stops new hosts at 100 % with live ones untouched, and General gets one line at 80 %.
  - C8: `cland host status` shows per pool the hosts, slots, and today's and the month's spend, and per host its size, region, uptime, sessions and price.

## Probes that mislead

- **Generated names cannot be certified by `qa lint`.** Loop titles are expanded in `expect.json` and checked by `tap.mjs` at the run; block-bodied loops stay `exact: false`.
- **`cland demo exec` has no stdin** and returns output when the command ends, capped at 8 MiB: the probes travel as single argument strings and the named files run one per exec.
- **Native files on the droplet.** E1534D-14, E1534D-24, E1534D-25 and E1534D-27 hold native T3 files; on the droplet they run in the delivered tree without the local preservation lock (the droplet is this run's alone). A native failure there is judged as it stands; it is not moved to the Mac to pass.
- **Idle stop versus lease expiry.** E1534D-65 judges idle stop only when the host is gone before the lease deadline read before the session stopped.
- **A missing transport is an outage, not a gone host.** Only a host the provider reports gone is settled at restart (E1534D-66); an outage is T-1753's 15-minute rule (E1534D-28).
- **Fake prices are zero.** Today's and the month's totals read `$0.0000`; the sub-cap and the 80 % line are E1534D-32's.
- **No CLI spend cap, outage, boot failure or DigitalOcean create.** These are component-only by design ("What the scratch hub cannot drive"); a scratch attempt to force one is out of scope.
- **Never the user's spend ledger.** The scratch hub, its watchdogs and the fake `release` write `$Q/executor-state/spend.json`.
- **Plain `node --test` is not the suite runner.** It enforces no duration allowance and no resource tripwire preload: a slow pass is not a finding and a fast one proves no budget.
- Process cleanup probes use the fixture-owned pid census (`$Q/pids`) and the scratch-root census; a machine-wide `pgrep` counts other sessions too.
- Speed criteria use hub-clock time in the named tests (5, 3 and 15 minutes, `idle_stop`), never wall-time projections.
- Re-check helper and function names with grep at `S`; renames happen. The kits come from commits `K` and `K3`; a different commit is a setup BLOCKED.
