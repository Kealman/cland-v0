## Pitfalls

- **Never run `cland release` in the root, not even `--dry-run`.** QA's role has no `release` permission (`hub/src/roles/permissions.ts`), and with E-426 open the root refuses anyway (R2). Running it through `noclu` would act as the human: that is routing around a refusal. The root attempt is the Coordinator's; QA reads it (R2) and reproduces the preview in P3 (R3). Never run a release without `--dry-run`, not even in P3.
- **`cland executor status` is refused to QA** (`executor controls belong to the Coordinator or the human`). Read the Coordinator's captures (`EXEC_CAP`); never run it in the root through `noclu`.
- **Identity.** QA's own commands (`cl`) act as QA on the live hub. Every scratch command (`c`, `c2`, `c3`, `as`, `ui`) runs through `noclu`. A scratch command that prints the live project's items, rules, sessions or topics reached the live hub: stop, record that check BLOCKED, and do not repeat it.
- **The DigitalOcean token.** No scratch hub may see `DIGITALOCEAN_TOKEN`: `guard` checks it before every start. Never print the token or any environment.
- **The `finish` file and the scratch lock.** `touch`/`rm $P/finish` and `mkdir`/`rmdir $LK` act only on scratch project `P`; check `echo $LK` first. A queued I1 run needs the scratch hold before its submit and its release after the commit.
- **Use `--fresh` for I1 and I2.** R0's green would otherwise make a same-tree request a cache hit that never queues or runs.
- **Time-box I2–I3.** RJ must still be live when I3 commits: if I2's wait runs long, record what arrived, skip the remaining wait and run I3 within 8 minutes of `I2-started-at`.
- **The copied item files in P3** come from `git show $S:` only. Never edit them; the only scratch tracker write there is R3's `task close E-426 --override`. Never copy a file into the live tracker.
- **Wait for state, not time.** `until_` waits on the state a check needs; `sleep` only settles before a negative read, and a negative read that could still change is INCONCLUSIVE, never FAIL.
- **Logs are large.** Grep them; never print a whole suite log.
- **Never work around a refusal.** A refused hold, demo control, close, preview or verdict is evidence: record its exact text.
- **One lease at most**, and only under decision 3b. Record D lines before `demo stop`.
- `qa-record.sh` takes `E-426` (and `R-294` in Appendix P1), and only the surfaces `headless-grid` and `hub-api` here. The verdict goes on `E-426`.
