## Pitfalls

- **One worktree.** `$W` is the build: never switch, edit or commit there. This brief makes no other worktree and no branch.
- **The windows.** The frozen window (to 14:45Z) must reproduce A-6112 exactly; the window to `S` is information. Do not mix them in one table.
- **`TO` is UTC.** Journal timestamps are `Z`; `TO` is built from `S`'s commit time with `toISOString()`. A commit time in `+02:00` compared as text would shift the window by two hours.
- **Process reads print counts, never command lines or environments.** The scripts print run ids, item ids, costs and counts only.
- **One lease.** Never run `demo start` twice. Record D lines before `demo stop`.
- **Commands on the droplet** are argument vectors: `sh -c '<script>'`, with `$e`, `$f` and `$PWD` inside the single quotes so the droplet's shell expands them. A test-name pattern passed to `dtp` contains no single quote.
- **Never work around a refusal.** A refused demo control or verdict is evidence: record its exact text.
- **Do not accept a miss, and do not call one.** QA records measurements and cites decisions; whether a value is accepted is the recorded decision's (D66), and whether a direct landing or a cover was allowed is the Coordinator's classification.
- `qa-record.sh` takes `E-678`. The verdict goes on `E-678`.

## Procedure

1. Choose a run id, `qa-<date>-<n>`, and set the Environment. Announce START in the request's topic, naming `S`. `dev` is not frozen: D14 decides.
2. Run, in order, recording each with `qa-record.sh` under `.cland/qa/E-678/<run>/` of the root:
   1. G0, G1, G2 and G3. If G0, G1 or G2 is not PASS, stop: the run is BLOCKED. G3 is information.
   2. Part D: D0, then D1–D6 one at a time on the one lease, D14, and D15 last of Part D.
   3. Part L: L1.
   4. Part R: R1, R2, R3, R4, R5.
3. Fix nothing. A failure is a finding: write down the check id, the command and what it showed.
4. The verdict is `clear` only when every check in scope is PASS. L1 `INCONCLUSIVE` (enforcement not live) and R3 `INCONCLUSIVE` (covers not classified) each make it `not clear` unless the epic or the request records the disposition the verdict rule names. Name each check that was FAIL, BLOCKED or INCONCLUSIVE.
5. If a step fails, keep what is already written and finish from there. Never rerun a check under the same run id; a D2–D6 rerun is the flaky rule's one rerun, in the same lease, reported beside the first result.
6. Before the verdict, run D14's freshness read again if `dev` moved since D14. Publish the evidence with `artifact.create` (kind `note`: the check table; the lease, executor, commit, lifetime and cost; the R1, R2 and R4 figures beside each target and the decision that accepts them; the R3 audit and cover list; the findings) **in the epic's topic where the request was delivered**, and name its id in the verdict text.
7. Write one verdict on E-678 from `$W`: `cl task comment E-678 "<text>" --verdict qa --result clear --run $RUN --commit $S --verified all`. A not-clear verdict carries only `failed` (one `{ criterion, note }` per failed criterion, single-line notes) and names in its text the criteria that passed. The text opens with the check table, then the findings ranked high, medium and low. If the hub refuses the verdict as `qa-stale`, keep the evidence and report BLOCKED. Any other refusal: fix its cause and write only the verdict again with the same run.
8. Release the hold if the verdict did not: `cl task hold E-678 --release`. Remove the build worktree: `git -C $R worktree remove $W`.
9. Report with `send` kind `report` to `lead E-678` in the request's topic: first line `qa clear E-678` or `qa not clear E-678`, then the failed checks, the criteria that rest on a recorded decision (D66) or on the Coordinator's classification, and the lease and its cost. Report any find outside the epic as a bug found aside, with its evidence, so the Coordinator files it under Bugs.

## Lessons applied from earlier runs

- E-676, E-425 and E-468: one lease; supporting test files one at a time on the droplet; a failure is rerun once and both results are reported.
- T-492: no secret or command line is ever printed; process checks print counts and ids.
- The cover-quiet rule and the load rule: while the Coordinator holds the verify slot, nothing heavy runs locally (`quiet`); no local full run or census while the crew is busy.
- D66 and T-775: a measurement the human accepted is checked for existence and reproducibility, not re-judged against the original target.
