# QA brief: E-423 Rules and rhythm

This brief is the Definition-of-done demo of epic E-423. QA runs it in the human's place, at a named `dev` commit, on a droplet through the demo lease this epic adds (decisions D16 and D19 of v0.1 §4: epics wait for no human demo). It has three parts.

- **Part D, the droplet.** One demo lease at the requested commit. On it: the build identity, the four headless workbench cases, a rulebook CLI round trip in a temporary project, and the epic's own test files, one file at a time.
- **Part L, local macOS, a scratch project.** A scratch project under `/private/tmp` with its own hub, running the requested commit's code from a clean detached worktree. The fake Claude Code and fake Codex harnesses play the Coordinator and the Implementer. Small driver spokes call the session tools. QA plays the human through the `cland` CLI. This part covers the rules reaching sessions, the heartbeat, `follows` with the merge hold, the verdict freshness rule, the size gate and the override scope. It never touches the live project's tracker, rulebook, crew or hub.
- **Part R, the live project, read-only.** The seeded rulebook, the memory marks, and the docs, clauses and skills.

Everything the run needs is in this file or in the files it names: whoever runs it cannot ask.

## Build

- **The worktree.** Use a clean detached worktree of the root at `S`: `W=$R/.cland/worktrees/qa-e423-$RUN`, made with `git -C $R worktree add --detach $W $S`. The root's tracker can have live edits, so never run from the root. Otherwise record G0 BLOCKED, naming both commits, and stop.
- **`dev` may move.** A `dev` that moves during the run does not block it. After the cases, `cland demo status E-423 --commit $S --json` reads `freshness`. `current: true` means every later commit avoids the files the epic's task merges changed. `current: false` names the conflicting commits and files, or says `S` is no longer on `dev`: keep the evidence and report to the requester, who asks for a fresh run. The hub applies the same rule when it records the verdict and when it closes the epic.
- **Never touch the root's crew, hub or tracker.** In the root and in `$W`, never run any of these:

  - `rule add|edit|retire`, `crew set`, `role set|clear`, `session …`, `merge`, `push`, `sync`, `release`;

  - `verify` in any form, except the read `verify queue --json`;

  - a workbench on the root.

  QA's own demo controls (`demo start|exec|status|stop E-423`) are allowed: they belong to QA holding the epic.

## Pitfalls

- **Identity.** QA's own commands (`cl`) act as QA on the live hub. Every scratch command (`c`, `as`, `ui`, the drivers) runs through `noclu`. A scratch command that prints the live project's items, rules, sessions or topics reached the live hub: stop, record that check BLOCKED, and do not repeat it.
- **The DigitalOcean token.** The scratch hub must never see `DIGITALOCEAN_TOKEN`: `guard` checks it before every start. Never print the token or any environment.
- **One lease.** Never run `demo start` twice. Record D lines before `demo stop`, so they carry the lease's executor, lifetime and cost. After `demo stop`, record with `QA_DEMO_EPIC` unset.
- **Commands on the droplet** are argument vectors: use `sh -c '<script>'` when a check needs a shell. Quote `$PWD` and `$T` inside the single quotes, so the droplet's shell expands them, not QA's.
- **Use the printed ids and numbers.** Every scratch id and rule number comes from a `--json` result. A number that differs from "at writing" is not a finding.
- **Wait for state, not time.** Wait with `until_` on the state a check needs (a session `idle`, a rule line in the fake's log, a firing in `hbs`). `sleep` is only a settle before a negative read, and a negative read that could still change is INCONCLUSIVE, never FAIL.
- **The busy fold needs the heartbeat off before the approval** (L35). Otherwise a new idle firing after the approval starts its own turn, and the count reads `N0 + 2`. That is not a finding: record it, note the firing ids, and judge by whether the queued heartbeat rode the next turn.
- **The fake Claude Code approves on SIGUSR1** to the session process (`pid coord`). The fake Codex approves on the file `approve` in its home, which then stays: L23 is the only Codex approval.
- **Ask ids.** An agent question becomes an ask only when it goes to the sender's next lead (the Coordinator, in General for an unbound question). If `AK` does not appear in the digest's in-flight part, record the exact send outcome and mark only that row INCONCLUSIVE.
- **Never work around a refusal.** A refused claim, edit, merge, verdict, demo control or rule write is evidence: record its exact text. Never retry it with `--force`, another identity or a hand edit (L13's two edits of the scratch `RULES.md` are the brief's own steps, in the scratch project only).
- **Never edit the live `.cland/RULES.md`, the memories, `roles.toml` or `crew.toml`.** Part R only reads.
- `qa-record.sh` takes `E-423` (one uppercase kind prefix and digits). The verdict goes on `E-423`.

## Lessons applied from earlier runs

- T-276, T-270: a driver never takes a reserved name; the scratch `origin` is its own territory; every scratch command strips QA's identity; `until_` waits on state, never on a flash.
- T-386: no full suite; supporting test files run one at a time; a failure is rerun once and both results are reported.
- E-423's own risk list: the demo lease shares `remote_budget` and the daily cap, so a budget refusal sends the demo to the local machine with the reason in the verdict, and the merge hold stays in force.
- The cover-quiet rule: while the Coordinator holds the verify slot, nothing heavy runs locally.
