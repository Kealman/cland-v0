# QA brief: T-110 Epic: Threads that read

This brief is the Definition-of-done demo of epic T-110, run by QA on `dev` in the human's place (decision D16: epics wait for no human demo). It checks the thread through headless-grid cases and a headless workbench on a scratch project with real history. Everything the run needs is in this file or in the files it names.

## Item

T-110: the thread reads: one block per message with a role gutter and delivery stage, Markdown per message, a rule per day, agent-to-agent runs folded, red verdict lines, ask cards, a readable 80-column layout, and a top-bar count of now-layer messages only. The demo is the narrative under `## Definition of done` (`task view T-110`); its eight checkboxes are C1..C8 in order. The five narrow-width breakages are listed in T-86 (`task view T-86`).

## Procedure

1. Choose a run id, `qa-<date>-<n>`.
2. Run every case and manual check above, in order, and record each with `qa-record.sh`.
3. Fix nothing. A failure is a finding: write down the case id, the command and what it showed.
4. Verdict `clear` only when every case and check in scope is PASS; otherwise `not clear`, naming each case that was FAIL, BLOCKED or INCONCLUSIVE.
5. If a step fails, keep what is already written, finish from there and never rerun a case under the same run id (the skill, "When a step fails").
6. Criteria: the ids are C1, C2, … in the order of the checkboxes under `## Definition of done` (check with `task view T-110`; if the ids differ from the order below, map by the checkbox text and say so). Verify with `--verified` exactly the ids whose checks are all PASS, as the "Proves" column says; a failed or BLOCKED check puts its criterion under `--failed "Cn=note"`, or leaves it unverified when BLOCKED. Never use `--verified all` unless every row is PASS.
6a. Until T-196 lands, the hub refuses criteria operations on an epic, so do not pass `verified` or `failed` on this epic's verdict. Write them in the verdict text instead, as two lines: `verified: C1,C3,…` and `failed: C2=note; …`.
6b. A check that needs the human or a real model harness (marked BLOCKED-likely above) is recorded as BLOCKED with its reason. It does not make the verdict not clear on its own: list it under `deferred to the T-117 walkthrough:` in the verdict text. Any other FAIL, BLOCKED or INCONCLUSIVE keeps the verdict not clear.
7. Through the hub: write it with `task.comment` (`verdict` qa, `result`, `run`, `commit`, and the verified/failed lines in the text) and `send` it to the coordinator as `qa clear T-110` or `qa not clear T-110`. Without a hub: print every `runs.jsonl` line, the case table and `verdict: qa`, `result:`, `commit:`, `run:`, `verified:`. The epic closes on a clear verdict once its children are closed (decision D16); the Coordinator closes it.
