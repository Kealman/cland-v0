# QA brief: T-115 Epic: Visibility and artifacts

This brief is the Definition-of-done demo of epic T-115, run by QA on `dev` in the human's place (decision D16: epics wait for no human demo). It checks the epic as a whole through the `cland` CLI against scratch hubs that launch only the fake Claude Code, one headless workbench at a time on those hubs, and the committed targeted tests as corroboration. Everything the run needs is in this file or in the files it names.

## Item

T-115: every workbench surface places what it shows in one of four layers (now, watch, background, archive) by one hub classifier (`hub/src/hub/visibility.ts`), overridable per project by `[visibility]` in `.cland/config.toml`; the human pins (`gP`) and mutes (`gM`) topics, sessions and artifacts, kept under `visibility` in `.cland/ui.json`; messages older than seven days leave the thread until `A`; an artifact is a file or a folder with an entry file; the human's and Aides' artifacts never expire, agents' artifacts follow their topic unless `kept`; `artifact.keep`, `artifact.move`, `artifact.archive`, the human-only `artifact.delete` UI frame and `cland artifact new | open | keep | move | archive | promote`; and the Artifacts browser in the centre. The demo is the narrative under `## Definition of done` (`task view T-115`). The epic's parent is the release T-130 (confirm it is `kind: release`). Its children T-166, T-171, T-190, T-191, T-192, T-193, T-194, T-195, T-205, T-208 and T-219 must all be closed before the run (`task list --under T-115`; list any other child found there in M0 and judge it the same way). T-115 lists T-110 and T-109 under `blocked_by`: record their states in M0 (not a reason to block, but name an open one in the verdict).

Decisions taken during the build that change how the DoD narrative reads. Apply them; they are not findings:

- **D17** (T-171, rescoped 2026-10-11): a not-clear verdict and a session death are **warn-level events**: Watch layer with `severity: "warn"` and an amber `⚠` marker in the inbox and the Agents log, never in `needsYou`, with no dismissal or resolution rule (`d` refuses them, `D` keeps them). The narrative's "an ask and a not-clear verdict on top" therefore reads: the ask in **NOW** at the top, the not-clear verdict as `⚠` under **WATCH**. The spec §3.5 table cells that put "a verdict not clear, a session died" in now are superseded the same way.
- **T-219**: `x` in the browser deletes after a confirmation (`vim.ui.select` with `Cancel` / `Delete`) through the human-only `artifact.delete` UI frame; agents get no tool and there is no CLI command.
- **T-192**: item layer filters `gn` / `gw` / `gb` / `gA`; messages older than seven days are archive, reached with `A`; pins and mutes (`gP` / `gM`) persist in `ui.json`. The centre board (`␣b`) keeps its open-parent scope (a closed epic's done cards leave it) while the items panel shows done tasks raised to now/watch even beneath a closed parent. Planned items outside the current release are `unscheduled` (background), not watch.
- **T-166**: both inbox views show the newest 50 notifications, newest first, with an `N earlier · Agents log (␣L)` footer beyond the cap.

## Pitfalls

- The scratch hubs and the workbench must never see the QA shell's `CLAND_*` variables (`noclu`). A command that prints the root project's items or sessions has reached the live hub: stop, record BLOCKED for that check, and do not repeat it.
- Never launch or stop a session, start or stop a hub, or write the tracker in the root. The only root write is the final verdict.
- `<Space>n`, `<Space>s`, `<Space>t`, `<Space>i` and `:Cland panel …` toggle: pressing the active one hides the panel. Check the panel window first.
- Status, layers and the inbox can lag about 2 s behind a write; re-read before judging.
- `c artifact open <id>` without `--json` launches `$VISUAL`, then `$EDITOR`, else `nvim`: always unset `VISUAL` and set `EDITOR=true` for it.
- `artifact list` takes no id; folder files come from `artifact open <id> --json` (`files`).
- The DB edit in M14 is the only hand edit, in the scratch project, with its hub stopped. Never hand-write item files, `ui.json` or the artifact index.
- `as` needs the session to be live in `c session list --json`; an empty `sessionId` makes the call act as an unknown roleless session and be refused for the wrong reason.
- T-222 (open): a post-merge stop of a Codex Implementer is recorded as a death. Nothing here merges or uses Codex; if a `⚠ … died` appears for a session you stopped with `session stop` (impl-3), record it as a finding citing T-222.
- **Load-sensitive tests: never run the full suite** (`npm test`, `cland suite`), and do not run these files at all in this brief: `hub/test/request-guard.test.ts` (T-172 timing), `nvim/test/plan.test.ts` (T-223, watch-marks/last-look `Invalid buf` under load), `nvim/test/thread.test.ts` (T-213 exception for its background-fold reconstruction case), the Codex launch/stop-wait and crew non-table refusal tests of T-213, `nvim/test/qa.test.ts` and `nvim/test/shell.test.ts` (long, shared fixtures).
