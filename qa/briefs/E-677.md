## Pitfalls

- **Two worktrees, two jobs.** `$W` is the build: never switch, edit or commit there. Plants go only in `X`, each on its own `qa/e677-$RUN-*` branch from `S`. Never push them; L3 deletes them.
- **No local tests.** `npm run test:lint` and the selection replay are the only commands that parse test sources on the Mac. Everything that runs a test file goes through `dx` on the lease.
- **The manifest is incomplete.** 57 files have no duration baseline at writing; the manifest totals are a lower bound. The integrated run's tier lines are the better measure, and they are what T-775 recorded.
- **Process reads print counts or census rows, never command lines or environments.**
- **One lease.** Never run `demo start` twice. Record D lines before `demo stop`.
- **Commands on the droplet** are argument vectors: `sh -c '<script>'`, with `$PWD`, `$e` and `$f` inside the single quotes so the droplet's shell expands them. Quotes inside a `node -e` script that sits in `dx sh -c '…'` are escaped as in Block D2.
- **Never work around a refusal.** A refused demo control or verdict is evidence: record its exact text.
- **Do not accept a miss.** QA records measurements; acceptance of a missed target belongs to a recorded decision.
- `qa-record.sh` takes `E-677`. The verdict goes on `E-677`.

## Procedure

1. Choose a run id, `qa-<date>-<n>`, and set the Environment. Announce START in the request's topic, naming `S`. `dev` is not frozen: D14 decides.
2. Run, in order, recording each with `qa-record.sh` under `.cland/qa/E-677/<run>/` of the root:
