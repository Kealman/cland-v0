## Probes that mislead

- The live hub runs code from its last restart (#57), before E-1310 landed, with no Telegram remote enabled. Its behaviour is no evidence. The tests at the build are.
- A `node --test` exit 0 whose name pattern matched nothing is not a pass: confirm the named cases appear in the output.
- `/inbox` keeps earlier copies working; only the >150-second outage catch-up marks an old copy "↓ Re-sent below" and removes its buttons. A live old copy after `/inbox` is correct behaviour.
- Replies to plan and Claude Code TUI notices go to General with a "re plan E-n:" / "re approval <session>:" reference (decision 2026-10-27 11:30Z, T-1358); request and item-topic notice replies go to their topic. Both are C3 behaviour, not a finding.
- A long ask is one card whose question is clipped at a word boundary with "full question in the workbench" (decision 2026-10-27 09:04Z, T-1353).
- Rich-to-plain fallback happens only on a 400 rejection; a 429 retries the same request and a 5xx stays fenced (E-1309 behaviour).
- T-1351 (a failed hub start at openDatabase leaks a FileHandle) is a known separate bug; its DEP0137 warning is not an E-1310 finding.
