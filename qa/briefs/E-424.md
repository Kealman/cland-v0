# QA brief: E-424 OpenCode v2 hygiene

This brief is the Definition-of-done demo of epic E-424. QA runs it in the human's place, at a named `dev` commit, mostly on a droplet through the demo lease (decisions D16 and D19 of v0.1 §4). It has three parts.

- **Part D, the droplet.** One demo lease at the requested commit. On it: the build identity; a scratch project with its own hub and the fake OpenCode (`hub/test/fakes/opencode/`), where QA launches an Implementer on OpenCode with no account and reads its database in the launch record, reads `cland doctor` for the database, the login line, the version notes and the two warnings, launches with a fake server that prints no listening line, rejects an approval, launches with several policy rows and `provider/model#high`, and reads the role clause `cland init` wrote; `npm run check:opencode`; and the children's own test files, one at a time. Everything OpenCode-shaped runs here against fakes, in a scratch `HOME`: the droplet is the isolated machine, and no real OpenCode account or database exists on it.
- **Part L, local macOS.** One check: the P3 reproduction (OpenCode's background service started on a default data directory never resumes a cland session) needs the real `opencode` binary. It runs once, from a clean detached worktree, only if the binary is installed on the Mac. The test sets its own scratch `HOME` and `XDG_*` directories and a local provider that holds every request, so no model call leaves the machine and the human's real OpenCode database and logins are never read.
- **Part R, the live project, read-only.** The rulebook (the interim rule retired), T-296's proof, the two experiment artifacts, the docs, the role clauses, the release skill and the items.

Everything the run needs is in this file or in the files it names: whoever runs it cannot ask.

## Changes since the last run

- Commands: `"$S:qa/..."` is now `"${S}:qa/..."` (zsh reads `$S:q` as a modifier); the brief tells QA to run its blocks with bash.

- `quiet()` fails closed: it reads `verify queue --json` for any holder (not only coord), fails on a queue read error, waits up to 10 minutes and returns 1 (record the local checks BLOCKED) if the slot is still held.
- Test-run helper `dt`: complete per-run log and exit code kept, nothing overwritten, exit code is the result.
- D4 polls `status` (stopped rows report `state` unknown), through new prelude helpers `status`/`untilstatus`.
- Build: added the same-SHA prerequisite and the INT_LOG_LINUX / INT_LOG_MAC statement (QA runs no verify).
- Local fallback: accepted way to run the checks, judged normally; the doctor checks D5-D7 are droplet-only (BLOCKED under the fallback) because the doctor must never run on the Mac.
- Substitutes that rest on a recorded test receipt (D4, D8b, D12, D13, L1) are PASS-with-basis; INCONCLUSIVE stays only for checks that were not run.
- D8b: the approval is raised by launching qa-rej with the approval-triggering brief (no `session send` exists); reject.mjs is copied by an argv/base64 helper (`cpto`), not by stdin.

- D9-D14: test files run through `dt`; complete per-file logs and the exit code are the evidence, not `ℹ` summary lines.
- R4: the documented exemptions are applied before a missing cell fails.

**The droplet prelude.** Write it once to `$EV/prelude.sh`. `dx` sends it with every droplet exec. Everything under `/tmp/qa-E424` on the droplet is scratch. `dt <test file> <id>` keeps the complete output of one test file in its own never-overwritten `$EV/<id>.log` and the exit code in `$EV/<id>.exit`; the exit code is the result and `ℹ` summary lines are not relied on (Node may emit TAP when piped).

```sh
cat > $EV/prelude.sh <<'EOF'

c()   { (cd $P && env $STRIP HOME=$HM FAKE_OPENCODE_HOME=$FO CLAND_OPENCODE_BIN=$FOC/opencode node $W/hub/bin/cland.ts "$@"); }
# hub start with the traps and fakes: OPENCODE_DB points at a trap database that must never reach a server
hubstart() { (cd $P && env $STRIP HOME=$HM FAKE_OPENCODE_HOME=$FO CLAND_OPENCODE_BIN=$FOC/opencode PATH=$FOC:$PATH OPENCODE_DB=$Q/trap.db \
  CLAND_ADAPTER_POLL_MS=200 FAKE_OPENCODE_TURN_MS=300 "$@" node $W/hub/bin/cland.ts hub start); }
js()  { node -e 'let s="";process.stdin.on("data",d=>s+=d).on("end",()=>{const v=JSON.parse(s);console.log(eval(process.argv[1]))})' "$1"; }
state() { c session list --json | js "v.processes.find(p=>p.name==='$1')?.state"; }
status() { c session list --json | js "v.processes.find(p=>p.name==='$1')?.status"; }
untilstatus() { for i in $(seq 1 ${3:-90}); do [ "$(status $1)" = "$2" ] && { echo "ok: $1 status $2"; return 0; }; sleep 1; done; echo "timeout: $1 status $2 (now $(status $1))"; return 1; }
untilstate() { for i in $(seq 1 ${3:-90}); do [ "$(state $1)" = "$2" ] && { echo "ok: $1 $2"; return 0; }; sleep 1; done; echo "timeout: $1 $2 (now $(state $1))"; return 1; }
lastlaunch() { c hub journal --kind session-launched --json | grep "\"session\":\"$1\"" | tail -1; }
```

**The reject script** (`$EV/reject.mjs`, then copied to the droplet as above). It finds the live fake server for the session from the session's own files, reads its mode-600 password file and sends one request; it prints only status codes.

```sh
cat > $EV/reject.mjs <<'EOF'
import { readFileSync, readdirSync } from 'node:fs';
const [name, hsid] = process.argv.slice(2);
if (!name || !hsid || hsid === 'undefined') { console.log('no exact session match: no harness session id'); process.exit(2); }
const dir = `${process.env.P}/.cland/opencode/${name}`;
const password = readFileSync(`${dir}/password`, 'utf8').trim();
const auth = { authorization: `Basic ${Buffer.from(`opencode:${password}`).toString('base64')}`, 'content-type': 'application/json' };
const servers = readdirSync(`${process.env.FO}/servers`).map(f => JSON.parse(readFileSync(`${process.env.FO}/servers/${f}`, 'utf8')));
let found = null;
for (const server of servers) {
  try {
    const sessions = (await (await fetch(`${server.url}/api/session`, { headers: auth })).json()).data ?? [];
    const session = sessions.find(s => s.id === hsid);          // the exact id from `session list --json`, never a title or "newest"
    if (session) { found = { server, session }; break; }
  } catch { /* another server: not this session's */ }
}
if (!found) { console.log('no exact session match for', hsid, 'on', servers.length, 'servers'); process.exit(2); }
const { server, session } = found;
const pending = (await (await fetch(`${server.url}/api/session/${session.id}/permission`, { headers: auth })).json()).data;
console.log('pending permissions', pending.length);
const reply = await fetch(`${server.url}/api/session/${session.id}/permission/${pending[0].id}/reply`, { method: 'POST', headers: auth, body: JSON.stringify({ decision: 'reject' }) });
console.log('reply status', reply.status);
EOF
```

The script never falls back to a title or the newest session. If it exits 2 or finds `pending permissions 0`, record what it saw: INCONCLUSIVE (not run), judged by D11 only if the session is alive.

## Pitfalls

- **Identity.** QA's own commands (`cl`) act as QA on the live hub. Every scratch command (`c`, `hubstart`) strips the `CLAND_*` variables and `DIGITALOCEAN_TOKEN` and sets a scratch `HOME`. A scratch command that prints the live project's items, sessions or topics reached the live hub: stop, record that check BLOCKED, and do not repeat it.
- **Secrets.** The server password lives in `$P/.cland/opencode/<name>/password`, mode 600. Never print it, never pass it in a command line; the reject script reads it itself. Never print the environment or a process command line (`pgrep` only with `| wc -l`).
- **Doctor only on the droplet, never `--fix`, never on the Mac.** Under the local fallback D5 to D7 are BLOCKED rather than run locally. The scratch project's doctor is read-only here; `--fix` could end other sessions' bridges on a shared machine.
- **Droplet exec quoting.** Commands are argument vectors; `dx` wraps each script in `bash -c` with the prelude. Inside `dx '…'` use `\"` for double quotes that the droplet's shell must see and `$VAR` for the prelude's variables. A quoting error that is not a product result is INCONCLUSIVE with the exact message, then fixed in a new command in the same lease.
- **One lease.** Never run `demo start` twice. Record D lines before `demo stop`.
- **The drafter did not run these commands.** The prelude, S0 and D5 to D16 are written from the README, the fakes' header comments and the children's tests. A flag name that the CLI rejects (`--relaunch`, `hub journal --kind`; there is no `session send`, see D8b) is a brief defect to report, not a product failure: use the nearest equivalent in `hub/README.md` and say so.
- **Never work around a refusal.** A refused demo control or verdict is evidence: record its exact text.
- `qa-record.sh` takes `E-424`. The verdict goes on `E-424`.

## Procedure

1. Choose a run id, `qa-<date>-<n>`, and set the Environment. Announce START in the request's topic, naming `S`. `dev` is not frozen: D17 decides.
2. Run, in order, recording each with `qa-record.sh` under `.cland/qa/E-424/<run>/` of the root:
   1. G0, G1 and G2. If any is not PASS, stop: the run is BLOCKED.
   2. Part D: D0, D1 and S0, then D2 to D16 on the one lease (D9 to D14 one test file per exec; D12b is recorded after L1). Then D17, and D18 last of Part D.
   3. Part L: `quiet` (BLOCKED for L1 if it returns 1), then L1. Part L may run beside the test files of D9 to D14.
   4. Part R: R1 to R5.
3. Fix nothing. A failure is a finding: write down the check id, the command and what it showed.
4. The verdict is `clear` only when every check in scope is PASS. A check that rests on a decision or a recorded test receipt (D5 and D13 on the 2026-10-16 amendment, D4, D8b, D12b and L1 on their named basis, R3 on the experiments being artifacts and not reruns) is PASS and says so in the verdict text. Otherwise it is `not clear`, naming each check that was FAIL, BLOCKED or INCONCLUSIVE.
5. If a step fails, keep what is already written and finish from there. Never rerun a check under the same run id; a D9 to D14 rerun is the flaky rule's one rerun, in the same lease, reported beside the first result.
6. Before the verdict, run D17's freshness read again if `dev` moved since D17. Publish the evidence with `artifact.create` (kind `note`: the check table; the lease, executor, commit, lifetime and cost; which checks ran where; the findings) **in the epic's topic where the request was delivered**, and name its id in the verdict text.
7. Write one verdict on E-424 from `$W`: `cl task comment E-424 "<text>" --verdict qa --result clear --run $RUN --commit $S --verified all`. A not-clear verdict carries only `failed` (one `{ criterion, note }` per failed criterion, single-line notes) and names in its text the criteria that passed. The text opens with the check table, then the findings ranked high, medium and low. If the hub refuses the verdict as `qa-stale`, keep the evidence and report BLOCKED. Any other refusal: fix its cause and write only the verdict again with the same run.
8. Release the hold if the verdict did not: `cl task hold E-424 --release`. Remove the build worktree: `git -C $R worktree remove $W`.
9. Report with `send` kind `report` to `lead E-424` in the request's topic: first line `qa clear E-424` or `qa not clear E-424`, then the failed checks, the lease and its cost. Report any find outside the epic as a bug found aside, with its evidence.

## Lessons applied from earlier runs

- E-425: doctor only on the droplet; every scratch command strips QA's identity; process checks print counts and pids, never command lines.
- E-423 and T-276: `until`-style waits poll state, never a flash.
- T-386 and E-423: no full suite; supporting test files one at a time on the droplet; a failure is rerun once and both results are reported.
