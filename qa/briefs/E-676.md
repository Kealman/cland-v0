## Pitfalls

- **Two worktrees, two jobs.** `$W` is the build and L2's candidate: never switch, edit or commit there. Plants go only in `X`, each on its own `qa/e676-$RUN-*` branch from `S`. Never push them; L8 deletes them.
- **G3 first.** A live hub started before the newest hub-code commit on `S` judges admission with older code. Do not run L1, L2, L5–L7 or L9 against it: record them BLOCKED and report.
- **`--fresh` on L2 only.** Without it L2 can be a cache hit on the integrated green at the same tree and show no task-run log of its own.
- **Dry runs only, except L2 and the conditional L3.** Never submit `verify all` without `--occasion epic`; L9 uses `--dry-run` so a wrong admission queues nothing.
- **Process reads print counts or census rows, never command lines or environments.**
- **One lease.** Never run `demo start` twice. Record D lines before `demo stop`.
- **Commands on the droplet** are argument vectors: `sh -c '<script>'`, with `$PWD`, `$T` and `$R` inside the single quotes so the droplet's shell expands them.
- **Never work around a refusal.** A refused verify, demo control or verdict is evidence: record its exact text.
- `qa-record.sh` takes `E-676`. The verdict goes on `E-676`.
