# QA brief: E-468 Run records: findings, escapes, answers, covers and sub-agent models as data

This brief is the Definition-of-done demo of epic E-468. QA runs it in the human's place, at a named `dev` commit (decisions D16 and D19 of v0.1 §4). It has three parts, all on the local Mac. No check needs Linux, so the brief starts **no demo lease**; `cland demo status --commit` still gives the freshness read without one.

- **Part L, a scratch project.** A scratch project under `/private/tmp` with its own hub, running the requested commit's code from a clean detached worktree, with the fake harnesses on its `PATH`. QA plays the human through the `cland` CLI; small driver spokes play a Coordinator and a Reviewer; a fake Claude Code session spawns sub-agents. It covers verdict findings, `found_by`, `answered_as`, cover records and sub-agent models. It never touches the live project's tracker, crew or hub.
- **Part T, targeted test files.** The children's own test files, one at a time, under the load rule.
- **Part R, the live project, read-only.** The Reviewer clause, the `code-review` skill and the README.

Everything the run needs is in this file or in the files it names: whoever runs it cannot ask.

## Pitfalls

- **Identity.** QA's own commands (`cl`) act as QA on the live hub. Every scratch command (`c`, `as`, `ui`, the drivers) runs through `noclu`. A scratch command that prints the live project's items, sessions or topics reached the live hub: stop, record that check BLOCKED, and do not repeat it.
- **The DigitalOcean token.** The scratch hub must never see `DIGITALOCEAN_TOKEN`: `guard` checks it before the start. Never print the token or any environment.
- **`topic answer` is the human's.** In the scratch project only, through `c`. Never answer a live ask.
- **Integrated means the Coordinator's shell in the root on `dev`.** A human run from the root is an ordinary run and records no cover.
- **Set `mode` before each run** and wait for its result before the next. L43 leaves a run waiting until `fin`.
- **Use the printed ids.** A number that differs from "at writing" is not a finding.
- **Never work around a refusal.** A refused claim, merge, verdict or classify is evidence: record its exact text.
- `qa-record.sh` takes `E-468`. The verdict goes on `E-468`.

## Procedure

1. Choose a run id, `qa-<date>-<n>`, and set the Environment. Announce START in the request's topic, naming `S`. `dev` is not frozen: F1 decides.
2. Run, in order, recording each with `qa-record.sh` under `.cland/qa/E-468/<run>/` of the root:
   1. G0, G1 and G2. If any is not PASS, stop: the run is BLOCKED.
   2. Part L: the scratch setup, then L1–L4, L10–L12, L20–L22, L40–L45, L30–L31, and L49 (always, even after a failure).
   3. Part T: T1–T5, one file at a time after `quiet`.
   4. Part R: R1–R4. Then F1.
3. Fix nothing. A failure is a finding: write down the check id, the command and what it showed.
4. The verdict is `clear` only when every check in scope is PASS. Otherwise it is `not clear`, naming each check that was FAIL, BLOCKED or INCONCLUSIVE.
5. If a step fails, keep what is already written and finish from there. Never rerun a check under the same run id; a Part T rerun is the flaky rule's one rerun, reported beside the first.
6. Publish the evidence with `artifact.create` (kind `note`: the check table and the findings) **in the epic's topic where the request was delivered**, and name its id in the verdict text.
7. Write one verdict on E-468 from `$W`: `cl task comment E-468 "<text>" --verdict qa --result clear --run $RUN --commit $S --verified all`. A not-clear verdict carries only `failed` (one `{ criterion, note }` per failed criterion, single-line notes) and names in its text the criteria that passed. The text opens with the check table, then the findings ranked high, medium and low. If the hub refuses the verdict as `qa-stale`, keep the evidence and report BLOCKED. Any other refusal: fix its cause and write only the verdict again with the same run.
8. Release the hold if the verdict did not: `cl task hold E-468 --release`. Remove the build worktree: `git -C $R worktree remove $W`.
9. Report with `send` kind `report` to `lead E-468` in the request's topic: first line `qa clear E-468` or `qa not clear E-468`, then the failed checks. Report any find outside the epic as a bug found aside, with its evidence, so the Coordinator files it under Bugs.

## Lessons applied from earlier runs

- E-423 and T-276: a driver never takes a reserved name; the scratch `origin` is its own territory; every scratch command strips QA's identity; `until_` waits on state, never on a flash.
- T-386 and E-423: no full suite; supporting test files one at a time; a failure is rerun once and both results are reported.
- T-544: sub-agent usage rows arrive in hook order, so L31 judges that order.
- The cover-quiet rule: while the Coordinator holds the verify slot, nothing heavy runs locally.
