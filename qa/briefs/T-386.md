# QA brief: T-386 Test speed: quick wins

This brief is the Definition-of-done demo of epic E-386. QA runs it on `dev` in the human's place (decisions D16 and D19 of v0.1 §4: epics wait for no human demo). It has four parts.

- **The two integrated logs.** The before run (A-2450) and the after run (the release cover, named in the QA request) are read, never re-run. They give the C1 comparison over the tests common to both, the timer-bound test times and the budget lines in a real full run.
- **Root reads and targeted files.** The `chooseSuiteMode` replay, the docs and clauses, the fake defaults, the manifest, and the proof tests of C6 and C8. Test files run **one file at a time**, under the queue rule.
- **Three scratch worktrees under `$R/.cland/worktrees/`.** A Neovim-only branch through `cland verify`, a planted over-budget test through the runner, and a clean detached copy for the census. They are local only: never pushed, deleted at the end.
- **One census** through the human queue, admitted alone.

QA runs no full suite of its own except the census, which the DoD asks for. Everything the run needs is in this file or in the files it names.

**The comparison script.** Write `$D/common.mjs`. It parses the column-zero `✔ … (ms)` lines (top-level tests, the research's method), keyed by name and occurrence, in the hub phases (`suite phase hub …`). It sums them over the keys present in both logs. It also lists tests of any phase that are present before and missing after:

```js
import { readFileSync } from 'node:fs';
const parse = path => {
  const lines = readFileSync(path, 'utf8').replace(/\x1b\[[0-9;]*m/g, '').split('\n');
  const hub = new Map(), all = new Set(), seen = new Map(); let phase = null;
  for (const line of lines) {
    const p = /^suite phase (.+?);/.exec(line); if (p) { phase = p[1]; continue; }
    const m = /^✔ (.+) \(([\d.]+)ms\)/.exec(line); if (!phase || !m) continue;
    const n = (seen.get(m[1]) ?? 0) + 1; seen.set(m[1], n); all.add(m[1]);
    if (phase.startsWith('hub')) hub.set(`${m[1]}#${n}`, Number(m[2]) / 1000);
  }
  const pick = re => lines.filter(l => re.test(l));
  return { hub, all, wall: pick(/^suite duration /).at(-1), finished: pick(/^Finished: /).at(-1), head: pick(/^Head /)[0], platform: pick(/^platform /)[0], mode: lines[1] };
};
const [a, b] = process.argv.slice(2).map(parse);
const common = [...a.hub.keys()].filter(k => b.hub.has(k));
const sum = m => common.reduce((s, k) => s + m.get(k), 0);
const wall = s => Number(/suite duration ([\d.]+)s/.exec(s ?? '')?.[1] ?? NaN);
const missing = [...a.all].filter(n => !b.all.has(n));
const strip = ({ hub, all, ...rest }) => ({ ...rest, hubTests: hub.size, allTests: all.size });
console.log(JSON.stringify({ before: strip(a), after: strip(b), common: common.length,
  beforeSeconds: +sum(a.hub).toFixed(2), afterSeconds: +sum(b.hub).toFixed(2), savedSeconds: +(sum(a.hub) - sum(b.hub)).toFixed(2),
  wallSavedSeconds: +(wall(a.wall) - wall(b.wall)).toFixed(2), missingAfterCount: missing.length, missingAfter: missing }, null, 2));
```

## Pitfalls

- **Identity.** QA's shell carries `CLAND_SESSION_NAME` and its siblings. Only M14's `cland verify` and the verdict run in QA's own identity. Root reads and test files use `noclu`. Runner and census runs use `hq`, which makes them human-queue hand runs. With `CLAND_SESSION_NAME` set, the runner skips the queue and takes the locks unseen: never do that.
- **The Neovim-only base.** The selection diffs `origin/dev...HEAD` plus working changes. A branch made from local `dev` while `dev` is ahead of `origin/dev` (unpushed tracker commits) carries `.cland/tasks` paths, and nvim plus anything else selects full. Base `$WN` on a freshly fetched `origin/dev` and check step 2's single path before submitting.
- **Cache.** `--fresh` keeps M14 from reusing a green tree. A cache hit records no run time and leaves M14 INCONCLUSIVE.
- **zsh.** Write `git show` arguments as `"${ref}:path"`. Unbraced, zsh reads `$ref:h…` as a history modifier.
- **Legacy log format.** A-2450 predates T-390's `suite timing` records. `common.mjs` reads the spec lines in both logs, so the two runs are counted the same way. Never mix the two record kinds.
- **Never work around a refusal.** A refused `verify`, a refused admission or a refused send is evidence: record its exact text, and never retry it with `--force` or another identity.
- **One file at a time.** Never start a test file, the M10 runner or M14 while another is running, and never while `local: coord`.

## Procedure

1. Choose a run id, `qa-<date>-<n>`, and set `RUN`, `EV`, `S`, `BEFORE` and `AFTER`. Announce START to the requester in the request's topic: `dev` is frozen for code until the verdict.
2. Run the checks in order and record each with `qa-record.sh`: M0 (if it is not PASS, stop: the run is BLOCKED), M1, M2 (if it is BLOCKED, record M3 BLOCKED and continue), M3 to M15, M16, M17.
3. Fix nothing. A failure is a finding: write down the check id, the command and what it showed.
4. Criteria:
   - **C1** = M2, M3
   - **C2** = M15
   - **C3** = M4, M14
   - **C4** = M5
   - **C5** = M6, M7
   - **C6** = M8
   - **C7** = M9, M10
   - **C8** = M11, M12
   - **C9** = M13

   M0, M1, M16 and M17 gate the run. Verify exactly the ids whose checks are all PASS. A safety failure (a run without human-queue admission, a lock touched, a scratch branch pushed) leaves every criterion it touched unverified.
5. If a step fails, keep what is already written and finish from there. Never rerun a check under the same run id (the skill, "When a step fails").
6. Publish the evidence with `artifact.create` (kind `note`) **in the topic where the request was delivered**. It holds the check table, the before/after table (M3, M6, M8's help median, M14, M15, each with load and holder) and the findings. Then write the verdict from the root in QA's own identity: `node hub/bin/cland.ts task comment E-386 "<text>" --verdict qa --result <clear|not clear> --run $RUN --commit <full git rev-parse dev> --verified <ids>` (clear), or with `failed` entries (not clear; see Verdict form). A QA verdict carries no `--scope`. The text opens with the check table, then the findings ranked high, medium and low, and names the artifact id.
7. Report: `send` kind `report` to the requester in the request's topic, `qa clear T-386` or `qa not clear T-386`. Without a hub, print every `runs.jsonl` line, the check table and `verdict: qa`, `result:`, `commit:`, `run:`, `verified:`.
