# QA brief: E-414 The approvals relay (Definition of done)

This brief is the Definition-of-done demo of epic E-414. QA runs it in the human's place, at the full `dev` SHA that the request names, and plays the human's part through the `cland` CLI, frame clients on the scratch hub's socket and its web edge (holding the web's cookie), one headless Neovim workbench and, for the web's marking of TUI-only records, Chrome Headless Shell. It has three parts.

- **Part D, the droplet.** One demo lease at the requested commit, through `cland demo` only. On it QA installs the helpers below, builds a sealed scratch area with one scratch project `p1` whose hub launches the fake `codex`, `opencode` and `claude` binaries through the production adapters, and walks the DoD's demo paragraph in order: three records, the web's Inbox, Codex Approve once and Always, OpenCode Deny with a note, two clients racing, answers in the harnesses' own TUI paths, nothing answered by itself, Neovim's inbox keys, the Claude Code TUI answer, a hub restart with requests pending, and `cland inbox`. It then runs the named test files that support each criterion.
- **Part L, local macOS.** The build gates in a clean detached worktree at the same SHA, the read-only live reads (the hold, the epic, its children and its plan), the docs, the epic occasion cover and the freshness check.
- **Fallback.** If the demo start is refused for lack of a remote slot or spend budget, every Part D row runs on this Mac in the worktree, unchanged, after `quiet`.

Everything the run needs is in this file or in the files it names: whoever runs it cannot ask. Commands are for bash (zsh reads `$S:q` as a modifier, and sourcing the sealed `env.sh` from zsh aborts): start `bash` first.
