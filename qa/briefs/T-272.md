# QA brief: T-272 Accounts and limits

This brief is the Definition-of-done demo of epic T-272. QA runs it on `dev` in the human's place (decisions D16 and D19 of v0.1 §4: epics wait for no human demo). It has two parts.

- **Part A, root reads and tests.** The children's hub and Neovim tests, **one file at a time**, two catalogue cases, a source scan and doc greps. Nothing is written in the root.
- **Part B, one scratch project with fake harnesses only.** Its own hub, a scratch `HOME`, a scratch `XDG_CONFIG_HOME` holding the registry (two Claude Code accounts, two Codex accounts, one OpenCode account), scratch default directories for every harness, and the three fakes in `hub/test/fakes/`. QA pins the Reviewer role to codex-b, launches a Reviewer and a Claude session on claude-b (and five more fake sessions), reads in the fakes' recorded environments that every adapter process ran in its account's directory, watches `claude agents --json` keep its 30-second schedule per directory and latch a signed-out directory once, reads the limits the fakes push in `cland account list` and the headless workbench's accounts block, sees idle accounts polled through their harness, marks codex-a, claude-b and oc-b limited with each harness's hard signal, sees launches refused naming the reset, and lifts the marks by hand and by reset. No launch moves to another account by itself.

**Safety in one line.** No real harness, account, token or `~/.config` is touched. Every scratch process runs under `senv` (Environment), whose `HOME`, `XDG_CONFIG_HOME`, `CLAUDE_CONFIG_DIR`, `CODEX_HOME` and `XDG_DATA_HOME` all point under `/private/tmp/qa-T-272*`, whose `PATH` starts with the fakes, and whose auth variables are dummies. `guard` refuses a hub start if any of those paths, or any path in the scratch registry, points elsewhere. Everything the run needs is in this file or in the files it names.

- **b11.** The `account-limits` journal record is written only on change.
- **T-265, the latch.** It lifts only on a pushed success (a session start or turn end without error; `StopFailure` never counts) or on an explicit launch whose `--bg` succeeds. A latched resume makes no CLI call; a live session stays watched with `state: unknown` and `stateReason: signed-out`. ## Pitfalls

- **Never run a scratch command outside `senv`** (`c`, `rs`, `ui`, `hubstart`, `nvstart`, the drivers and the attach runs all use it). A bare `claude`, `codex` or `opencode`, or a `cland` without `senv`, can reach a real harness, real account or the live hub. A command that prints the root's items, sessions or the human's accounts reached the live hub: stop, record BLOCKED for that check, and do not repeat it.
- **Never write a registry outside `$X`**, and never put a secret, even a fake one, into `$X/cland/accounts.toml` except M15(d)'s refused `token` line, restored at once.
- **Never work around a refusal.** A refused launch, relaunch or clear is evidence: record its exact text. Never edit `hub.db`, `ui.json`, the journal or a fake's record by hand. The fake input files (`rate-limits.json`, `usage-report.json`, `logged-out`, the hold/release files) are the fakes' documented controls, not workarounds.
- **Remove the hold.** `hold-rate-limits-read` holds every Codex `account/rateLimits/read`, idle polls included. M21(b) removes it with its release at once.
- **Do not message cb-1 while claude-b is latched** (M20 c–f): a successful turn is a pushed success and lifts the latch.
- **Capture Codex server records while the session runs**: the fake removes `servers/<pid>.json` when the app-server exits.
- **`gg` in the sessions panel lands on the Accounts header** (T-365): select a session by search (`/rev-1.*Reviewer<CR>`), never by line number.
- **Restarts.** After each `hub stop`/`hubstart`, `dstop` and `dstart` every driver, and quit the workbench first (M24 a). The `account` event listener ends with the hub; start it again only if a later check needs it.
- **Use the printed ids and pids.** A different pid, harness id or thread id than an example is not a finding.
- **Claimant done marks.** This run lands nothing through `cland merge`. If a later amendment adds a scratch landing, mark each criterion done as the identity that claimed the task before the review verdict (T-270's amendment 1): readiness needs a current `done` and a current `verified` mark on every criterion.
- `qa-record.sh` takes `T-272`, never `E-272`. Root reads use `--json` (T-339).
