# QA brief: E-1468 — Definition of done (Coordinator delivery never goes silently deaf)

## Item

E-1468, Definition of done C1–C3 (`cland task view E-1468 --json`). Children: T-1469 (a Claude Code poll must not turn a pushed idle into busy), T-1470 (held deliveries drain on any idle observation and on a timer), T-1471 (one harness process per Claude Code launch; an earlier-launch spoke is refused), T-1472 (`deaf` state, human notice, stage-specific recovery command), T-1473 (`session retry` forces a held queued human delivery), T-1474 (detect Claude daemon idle retirement), T-1475 (truthful bridge and flush logs). The demo is test-file runs plus read-only checks. No live Claude daemon, no real remote.

C1. The incident's sequence is replayed in a test: idle hook, then a poll reporting busy, then a human send, then idle. The message is injected within 60 s.
C2. A relaunch leaves one Claude Code process for the session, and a spoke from an earlier launch is refused.
C3. A live session holding a human delivery for over 5 minutes is shown as `deaf`, the human is told, and `cland session retry` releases it.

## Probes that mislead

- The live hub's own delivery state (its session rows, held queue, journal) is not evidence for any criterion. It runs code from its last restart. Use the tests at the build.
- A replayed id after a hub restart must NOT raise `deaf` or an inject-stalled alert (T-1472 C4). Use the restart-replay test in M4, not the live journal.
- `vm.memory_pressure` is irrelevant here; do not cite it.
- Several children landed under the rule 6 waiver (verify at the parent head, targeted post-merge receipts, delta review). That is accepted carried evidence. Record the parent head versus the landed head in the verdict as a distinction, not a finding.
- A `deaf` state is not a model failure: it means a live harness holds a human delivery over 5 minutes. A poll-only busy expires after 5 minutes by design (T-1470 C3); push busy does not.
- Fake-clock tests prove timings by advancing the clock; real elapsed time of the test run is not the 60 s or 5 min bound.
