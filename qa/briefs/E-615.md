## Pitfalls

- **Canonical scratch paths.** The scripts use `pwd -P` (`/private/tmp/…` on macOS). A v0.1.3 project initialised through a symlinked path (`/tmp/…` on macOS) records its `origin` URL under that path; the current `cland update` resolves the real path, no longer recognises `origin` as the territory and renames it to `github`. D6 prints `origin renamed: 0` to show the run avoided it. If it prints `1`, record D6 as FAIL on that line only and report it as a bug found aside.
- **Order on the lease.** D3 empties `/tmp/qa-e615` and writes `manifest.cjs`; D6 needs it; D7 needs D6's project; D8 needs D7's. Never rerun one alone.
- **The real `HOME` for Codex only.** `codex debug prompt-input` needs `~/.codex`; every `cland` call runs under `sc`/`env -i` with scratch `HOME` and `XDG_*`.
- **One lease.** Never run `demo start` twice. Record D lines before `demo stop`.
- **Commands on the droplet** are argument vectors: `ds` passes each script as one `sh -c` argument; nothing in it is expanded by QA's shell.
- **Never work around a refusal.** A refused demo control or verdict is evidence: record its exact text.
- `qa-record.sh` takes `E-615`. The verdict goes on `E-615`.

1. Choose a run id, `qa-<date>-<n>`, set the Environment and write the Scripts. Announce START in the request's topic, naming `S`. `dev` is not frozen: D14 decides.
