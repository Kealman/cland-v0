# QA brief: E-413 Hub-computed fields and read marks (Definition of done)

This brief is the Definition-of-done demo of epic E-413. QA runs it in the human's place, at the full `dev` SHA that the request names, and plays the human's part through the `cland` CLI, a frame client holding the web's cookie and one headless Neovim workbench. It has three parts.

- **Part D, the droplet.** One demo lease at the requested commit, through `cland demo` only. On it QA installs the helpers below, builds a sealed scratch area with two scratch projects and their hubs, and walks the DoD's demo paragraph step by step, in order: the Lua differential, the card facts, the unread count, the merged session row, the shared marks between headless Neovim and the frame client, the warnings filter, the fold line and the two answered asks. It then runs the named test files that support each criterion.
- **Part L, local macOS.** The build gates in a clean detached worktree at the same SHA, the read-only live reads (the hold, the epic, its children and its plan), the docs and role-clause statements, and the freshness check.
- **Fallback.** If the demo start is refused for lack of a remote slot or spend budget, every Part D row runs on this Mac in the worktree, unchanged, after `quiet`.

Everything the run needs is in this file or in the files it names: whoever runs it cannot ask. Commands are for bash (zsh reads `$S:q` as a modifier): start `bash` first.

## Probes that mislead

- Process cleanup probes use a fixture-owned pid/process-group census, registered at launch and checked through exit; a machine-wide `pgrep` counts other sessions too. Here every scratch hub, frame client, driver, driver spoke and the Neovim process append their pids to `/tmp/qa-e413dod/pids`, and E413D-21 judges those only (A-9063 R2; E-413 stage 1/T-1093).
- Edit existing keys in initialized configs, list standalone-test build prerequisites, enumerate regular files only for file probes, and identify events by seq/id. A second-client check allows only defaults the new client writes itself (A-8634 R12; E-412 stage 2, E-415 stage 3/DoD, E-1006). When Neovim starts on p1, the harness's `isolateVerification` rewrites p1's `.cland/config.toml` with a scratch `lock_path`: expected, not a finding.
- Transcript assertions identify stable item/topic/frame ids, with intervals starting at the result frame of the state-changing request. Preserve unaltered captures when correcting a probe and label the correction separately from product failures (A-8634 R13; E-412/E-415/E-1006; A-9063 R2; E-413 stage 1/T-1093). Model frames (`marks`, `message`, `ask`, `inbox`, `topic`, `session.row`) interleave with the frames a check causes: identify rows by item id, topic id, ask id, run id, message text or result id, never by position.
- Exact tracker copies replace the initialized tracker directory after its writers stop; copy the committed directory whole, dotfiles included, and compare that same file set. Apply the full `fixtureEnvironment` result after overlays, including synthesized values; under rule 15, check zero credential-prefix names before launching scratch processes and report names/counts only (A-9063 R2; E-413 stage 1/T-1093).
- The web edge refuses any frame carrying `as` (`cli-neovim-only`): the human's verdict comments go through the scratch CLI, never through `wc.cjs`. A `cli-neovim-only` refusal of a frame this brief sends is a brief defect, not a product failure.
- A thread in view is read by Neovim itself: Neovim opens on General, so the read-mark probe uses the topic `QA unread`, which Neovim never opens. An unchanged `marks.set` publishes no `marks` frame.
- `nvim/test/harness.ts` swaps the test process's environment for its own fixture HOME at startup; `nv.test.mjs` passes `QA_W` and `QA_Q` to `wc.cjs` explicitly. A `wc.cjs` crash naming `QA_Q` means that hand-off broke: a brief defect.
- `cland demo exec` has no stdin and returns the output only when the command ends, capped at 8 MiB; that is why the helpers are installed through base64 and checked by SHA-256 (E413D-04), each step script runs whole in one exec, and the captures come back as one gzip tar (E413D-21). The scratch hubs are daemons and outlive an exec; clients and drivers live only inside their step script.
- Run ages and outcome times come from the hub's clock: compare a run seen at two times without `ageMs` and its suffix, and compare an outcome's `at` across the card, the history, the departure and the archive, not with the answer message's `ts`. A hub notice in General between the probe messages splits a run by design: E413D-14 names such intruders and is INCONCLUSIVE, not FAIL.
- The scratch copy has no dev landing receipts: a stage's `merged` count and state there are not evidence either way; the stage counts' rule is E413D-16's named test.
- `cland web`, `hub start` and `hub stop` refuse a session's shell: a refusal naming "only the human" in E413D-06 means the environment leaked (rule 15), not a product fault.
- File-change probes use isolation; mtime alone is confounded by live sessions rewriting the same file. Nothing here reads the live tracker or `ui.json`.
- A "ran" marker grep excludes the configuration echo line.
- Successful droplet prepare logs are in the run's `delivery.log`, not the suite log.
- Speed criteria use measured wall times, never projections: this epic has none; the fold line's `ageMs` bounds are facts of the run, not speed criteria.
- Slots due or queued before the build count even when their results arrive later.
- "No skip": the hub test files are platform-independent; the Neovim parts (E413D-07's oracle, E413D-11, E413D-17's and E413D-18's Neovim files) need the pinned Neovim and are BLOCKED, not PASS, without it. Under the fallback the named tests check the live hub's cover slot themselves (`suite.slot`): an admission timeout is BLOCKED; retry after `quiet`.
