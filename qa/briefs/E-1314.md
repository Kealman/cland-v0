# QA brief: E-1314 Release v0.3.0 from the item (Definition of done)

This brief is the Definition-of-done demo of epic E-1314, **up to the dry run**. QA runs it in the human's place (D16 and D19 of v0.1 §4; spec v0.3 §4), at the full `dev` SHA the request names, and plays the human's part on the fakes as the DoD says: through the `cland` CLI, the fake platforms' control APIs (the fake Bot API, the fake Discord gateway and REST, the fake speech provider), Chrome Headless Shell and a headless Neovim. **The live run (C3) is not repeated here**: it ran with the human on the sandbox bots under `qa/briefs/E-1314-live.md` and is cited (E1314D-17). The epic closes on QA's clear verdict; the Coordinator then shows the dry run in an ask and releases from its own shell (the `release` skill). QA's post-release tag check is a separate request on R-1278, not part of this verdict. The run has two parts.

- **Part D, the droplet.** One demo lease at the requested commit, through `cland demo` only. QA installs the helpers below, builds the sealed environment and the web bundle, runs T-1442's integrated scenario `hub/test/scenarios/remotes.test.ts` alone (the integrated pass, C2), then the supporting hub, Web, Neovim, docs and release test files one file at a time, then walk 3: R-1278's item dry run reproduced in a scratch release project (C5, C1). It scans the captures for the fixtures' made-up credentials, pulls them and releases the lease at once (E1314D-13).
- **Part L, local macOS.** Read-only live reads: the scenario's assertions at `S` mapped to the DoD (C2); R-1278's open items and every other epic's closing QA verdict (C1); the live run's evidence (C3, cited); the version, R-1278's `## Notes` and the Coordinator's root dry-run attempt (C5); a fresh reading of the two remote pages (C4); the brief's lint; the Coordinator's two release covers at `S`, cited and never run by QA (C6); and, immediately before the verdict, the freeze and freshness check.
- **Fallback.** If the demo start is refused for lack of a remote slot or spend budget, every Part D row runs on this Mac in the worktree, unchanged, after `quiet`. Part L is local either way.

**Safety in one line.** QA never runs `cland release` without `--dry-run` anywhere, never runs any `cland release` on the live hub (not even `--dry-run`: GAP-1), never pushes, runs no full suite and no occasion, uses no real token, bot, Discord application or server and no real speech key (fakes and their made-up values only), never reads, prints or copies `~/.config/cland/sandbox-remote.secrets.toml` or any `.cland/secrets.toml`, opens no real browser (rule 18) and runs every scratch command sealed in a scratch project of its own (rule 15).

Everything the run needs is in this file or in the files it names: whoever runs it cannot ask. Commands are for bash (start `bash` first; zsh reads `$S:q` as a modifier and aborts on the sealed `env.sh`).

## Verdict

Clear only when every check E1314D-00 to E1314D-24, E1314D-COVER and E1314D-MAC is PASS (E1314D-02 as `local fallback` counts; **low** findings do not block). On `clear`: `--verified all` (C1 to C6; C2 by substitute for GAP-3 and GAP-4, C3 by citation of A-13972, both named so). The close gate needs every criterion verified in this run at `S`. On `not clear`, verify only the criteria whose mapped checks all passed and give each other one `--failed "Cn=<one-line note>"`.

The text opens with the check table (id, where, result, evidence), then: the executor (droplet, or local macOS with the quoted refusal), the full `S` (and any QA-hold commit beside it), lease, deadline, lifetime and cost, the freeze and freshness result, the C1 table (each epic, its verdict's run and commit), C3's cited run, artifact and not-verified scope, the two covers' run ids, artifacts, executors, platforms, wall times and costs, `DRY_ART` and walk 3's preview, the gaps per criterion (GAP-1 to GAP-6), and the findings ranked high, medium, low.

Write it with `cl task comment E-1314 "<text>" --verdict qa --result <clear|"not clear"> --run "$RUN" --commit "$S" --verified <ids>`, and `send` kind `report` to `lead E-1314` (the Coordinator) in the request's topic as `qa clear E-1314` or `qa not clear E-1314`. Then `cl task hold E-1314 --release` and remove the build worktree (`git -C "$R" worktree remove "$W"`, removing its `node_modules` link first if Git refuses). A verdict refused after the evidence was recorded is retried only as the verdict while the build still qualifies. The Coordinator closes the epic, then shows the dry run in an ask and releases.
