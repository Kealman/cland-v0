## Procedure

1. Choose a run id, `qa-<date>-<n>`, and set the Environment. Announce START in the request's topic, naming `S`. `dev` is not frozen: F1 decides.
2. Run, in order, recording each with `qa-record.sh` under `.cland/qa/E-387/<run>/` of the root:
   1. G0, G1 and G2. If any is not PASS, stop: the run is BLOCKED.
   2. Part E: E1–E7.
   3. Part T: T1–T8, one file at a time after `quiet`.
   4. Part R: R1. Then F1.
3. Fix nothing. A failure is a finding: write down the check id, the command and what it showed.
4. The verdict is `clear` only when every check in scope is PASS. Otherwise it is `not clear`, naming each check that was FAIL, BLOCKED or INCONCLUSIVE.
5. If a step fails, keep what is already written and finish from there. Never rerun a check under the same run id (the skill, "When a step fails"); a Part T rerun is the flaky rule's one rerun, reported beside the first.
6. Publish the evidence with `artifact.create` (kind `note`: the check table, the census count, the shard times and costs, the findings) **in the epic's topic where the request was delivered**, and name its id in the verdict text.
7. Write one verdict on E-387 from `$W`: `cl task comment E-387 "<text>" --verdict qa --result clear --run $RUN --commit $S --verified all`. A not-clear verdict carries only `failed` (one `{ criterion, note }` per failed criterion, single-line notes) and names in its text the criteria that passed. The text opens with the check table, then the findings ranked high, medium and low. If the hub refuses the verdict as `qa-stale`, keep the evidence and report BLOCKED. Any other refusal: fix its cause and write only the verdict again with the same run.
8. Release the hold if the verdict did not: `cl task hold E-387 --release`. Remove the build worktree: `git -C $R worktree remove $W`.
9. Report with `send` kind `report` to `lead E-387` in the request's topic: first line `qa clear E-387` or `qa not clear E-387`, then the failed checks. Report any find outside the epic as a bug found aside, with its evidence, so the Coordinator files it under Bugs.
