# QA brief: E-611 The Aide's reach and the settings commands

This brief is the Definition-of-done demo of epic E-611. QA runs it in the human's place, at a named `dev` commit, on one droplet through the demo lease (decisions D16 and D19 of v0.1 §4). Nothing in this demo needs macOS. It has three parts.

- **Part S, scratch projects on the lease.** Three scratch projects under the lease's `/tmp/qa-e611/`, with a scratch HOME, scratch XDG directories, a scratch Git identity, the fake harnesses and a fake `gh`. QA plays the human: it launches an Aide, asks it to launch, stop and resume sessions, to import a fake repository's open issues and to run `cland push`, sees an Implementer refused the same calls, sets launch fields, config values and lists models, and checks the new-project templates, `CLAUDE_CONFIG_DIR` and rule titles (C1–C6).
- **Part T, the children's own test files on the lease**, one at a time (C1–C6).
- **Gates and records, local macOS, read-only**, plus the hold, the lease controls, the freshness read and the verdict.

Everything the run needs is in this file or in the files it names: whoever runs it cannot ask.

## Pitfalls

- **Two identities.** `cl` acts as QA on the live hub: the hold, the lease, the freshness read and the verdict only. Every scratch command runs inside `dk`, whose `env.sh` unsets every `CLAND_*` variable and `cd`s into `/tmp/qa-e611/…`. A `dk` output that shows the live project's items, sessions or topics reached the live hub: stop, record that check BLOCKED, and do not repeat it.
- **Order matters.** A6 drives a second spoke as aide-1, so it runs after the last `ask aide-1` (D6). D6 sets `verification.workers` last: a value that needs a restart makes every later live-applied `config set` answer `saved; not applied`. F2 restarts P1's hub, so it runs after A6.
- **Quoting.** `ask` passes words; the fake Aide splits its prompt on spaces. Never ask for a value with a space in it.
- **Audit rows** reach `.cland/log/hub.log` a moment after the call; `audit` waits 3 s. If a row is missing, rerun only the audit line by hand on the lease (`dx sh -c '. /tmp/qa-e611-kit/env.sh && (cd $P1 && node $CL hub audit --session aide-1 --json)'`) before judging, and say so.
- **Process reads print counts, never command lines or environments.** `inv` prints only the session name, launch or resume, the permission flags and `CLAUDE_CONFIG_DIR`.
- **One lease.** Never run `demo start` twice. Record every lease line before `demo stop`.
- **Never work around a refusal.** A refused demo control, hold or verdict is evidence: record its exact text.
- `qa-record.sh` takes `E-611`; its surface is `hub-api`. The verdict goes on `E-611`.

## Lessons applied from earlier runs

- E-425, E-426: every scratch command strips QA's identity and the DigitalOcean token; scratch hubs take their own lock path and the local executor before their first start; the fakes come first on the scratch hub's `PATH`.
- E-676: one lease; test files one at a time on the lease, a failure rerun once in the same lease and both results reported. qa-record.sh refuses any surface but `headless-grid`, `tmux`, `web-terminal` and `hub-api`: lease checks are `hub-api`, with `QA_DEMO_EPIC` set for the executor and cost.
- T-492: no secret, environment or command line is ever printed; process checks print counts.
- The cover-quiet rule: under the local fallback nothing runs while the Coordinator holds the verify slot (`quiet`).
