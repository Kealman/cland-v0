# QA brief: E-419 The phone and notifications (Definition of done)

This brief is the Definition-of-done demo of epic E-419. QA runs it in the human's place, at the full `dev` SHA that the request names, and plays the human's part as the DoD says: through the `cland` CLI (every browser sign-in link comes from `cland web --no-open` or `cland web --qr`, and every session change is read back with `cland session list`) and headless Chromium at 390x844 with touch and the mobile flag: the suite's Chrome Headless Shell for the phone screens, and the full Chromium build, on this Mac only, for the two checks that need the real API (installability and a real notification through the service worker). It has three parts.

- **Part D, the droplet.** One demo lease at the requested commit, through `cland demo` only. On it QA installs the helpers below, builds the sealed environment and the web bundle, and walks the DoD's demo paragraph in eight walks, in its order: the inbox as home, the bottom bar and More's three read-only areas (walk 1); a fake Implementer's question forwarded to the human, the sheet on the keyboard, Escape, the scrim and a swipe leaving it open, Decline with a reason reaching the fake, and the folded row until QA leaves the Inbox (walk 2); a topic full screen, a run unfolded, a Return in the composer, Send, a queued message withdrawn and a draft across a reload (walk 3); the session rows, the queue sheet, a waiting session's page with its command and Stop after the confirmation (walk 4); the hub stopped and restarted under the disconnected strip (walk 5); the waiting plan, the Claude Code approval and the HTML chip (walk 6); the manifest, the start URL, More's notification controls and `cland web --qr` (walk 7); the tunnel guide's `[web]` snippet on a scratch hub (walk 8). It then runs the named test files that support each criterion. Once every droplet row and the captures are recorded, QA releases the lease at once (E419D-20).
- **Part L, local macOS.** The build gates in a clean detached worktree at the same SHA, the read-only live reads (the hold, the epic, its children and its plan), the full Chromium build fetched into the run's scratch root and walk 9 with it (installable on loopback with only the automation's own error; a new ask raising a real notification through the service worker), the build deleted, the typecheck with the web guards and T-1175's source checks, the `web/` rules of `AGENTS.md`, the docs with the tunnel guide, the brief's lint, the Coordinator's epic cover (cited, never run by QA) and, immediately before the verdict, the freshness check.
- **Fallback.** If the demo start is refused for lack of a remote slot or spend budget, every Part D row runs on this Mac in the worktree, unchanged, after `quiet`. Part L is local either way.

Everything the run needs is in this file or in the files it names: whoever runs it cannot ask. Commands are for bash (zsh reads `$S:q` as a modifier, and sourcing the sealed `env.sh` from zsh aborts): start `bash` first. Binary formats (PNG headers, the app bundle's property list) are decoded with Node, never with `od` or `awk`.
