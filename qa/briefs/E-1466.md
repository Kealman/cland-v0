## Probes that mislead

- The live hub's own memory (its RSS, `ps`, Activity Monitor) is not the demo's evidence. The hub runs code from its last restart on a different load, with clients and crew. The scratch-copy artifacts and the test at the build are the evidence. Live figures from R-1465 and A-14701 are quoted as context only.
- A budget-check exit 0 is not a pass of the budget. The probe and `memoryBudgetReport` are report only: they write `memory-budget.json` and never gate. The readings in that file, compared with 256 MiB and 768 MiB, are the pass; `unavailable` or `unconfigured` is neither pass nor zero.
- `vm.memory_pressure` (the transient counter, which can spike to thousands) is not the pressure level. The level is `kern.memorystatus_vm_pressure_level` (1 is normal); the probe's guard uses the level, and the counter and free-memory percentage are context only (the two "pressure" cases in M3 assert this). A high counter with level 1 is not a failure.
- Heap and RSS are not additive. Array buffers are inside external; RSS minus heap is not a measure of SQLite or native memory; vmmap categories (footprint, swapped, malloc zones) use their own units. A-14160 says SQLite native memory could not be separated: that is a stated unknown, not a missing item.
- Sampling profiles (1 MiB interval) give new surviving sampled allocations, not retained sizes. The "~1648 MiB" and "~1068 MiB" rows are attribution estimates; a reviewer must not read them as exact bytes.
- Heap readings are unforced (no GC); the T-1477 post-selection heap (116.33 MiB at the indexing-tracker checkpoint) moved from an earlier 61.019 MiB reading by GC timing, as A-14201 states. Compare checkpoints with the same name only.
- At-rest slopes: whole-window RSS slope +0.054 MiB/min and post-120 s +0.113 MiB/min are slow positive, not zero; heap is slightly negative. The artifacts state this; do not round either way.
- The 10-minute diagnostics (A-14690) are context, not the final record; only the 1800 s record (A-14699/A-14701) at aa8e5ecdf carries the configured budget. Earlier receipts without a configured budget are never retroactive passes.
- Footprint (physical footprint) is a rounded native display value, not exact allocation bytes, and it differs from RSS because it includes compressed and swapped pages.
- Machine state affects the occasion, not the code: used swap near 90%, a busy crew or `fseventsd` growth can make readings or the guard misbehave. Record load, swap and `kern.memorystatus_vm_pressure_level` beside any M4 run; it does not change a criterion's verdict by itself unless the guard stops the run.
- A `node --test` exit 0 whose selected name matched nothing is not a pass: every name in M3 must appear in the output as run.
