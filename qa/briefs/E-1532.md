# QA brief: E-1532 — Definition of done (The SSH transport, the host agent and git through the tunnel)

This brief is the Definition-of-done demo of epic E-1532 (qa skill, "Epic demos on a named dev commit"). QA runs it in the human's place at a named `dev` commit and records one epic verdict that names, by id, the criteria it verified (C1–C10). Everything the run needs is in this file or in the files it names: whoever runs it cannot ask. Commands are for bash (zsh reads `$S:q`, `$B:h` or `${B}:hub` as modifiers; always brace a variable before `:`).

**Where it runs.** Locally, on macOS (BSD `stat -f`, `lsof`, `uuidgen`, Node 24 with `node:sqlite`), from a clean detached worktree at the requested SHA, with `QA_DEMO_EPIC` unset. There is no `cland demo start`, so no lease, deadline, lifetime or cost: the DoD names no droplet ("No real provider, droplet or key is involved"), and `cland demo status` reads freshness without a lease. **No real SSH, host, droplet, volume, key or network (R-1530's QA rule):** the carrier runs only through the fake `ssh` and `scp` of `hub/test/fakes/` against two fake hosts made by the build's own `createFakeHost`; their agents are the build's `cland host serve` under the shipped supervisor, as local processes. **No real harness:** Claude Code, Codex and OpenCode run only as the build's fakes. No browser, no GUI. A platform skip is a FAIL, not a pass.

The run has three parts, framed by gates and a freshness check:

- **Part T, named tests at S** (E1532D-02 to E1532D-13). The source strings (E1532D-02), then one row per criterion C1–C9 (E1532D-03 to E1532D-11) with the landed test files and their generated cases, the ADR amendments (E1532D-12, C10) and the slim spoke's evidence (E1532D-13).
- **Part C, the full suite** (E1532D-14). QA re-reads the stage-7 cover pair at tree `d01df777` (dev `ca3a07f1`): Linux `1b9279d1` (`A-17168`) and macOS `c206238f` (`A-17176`), and checks with `git diff --name-only ca3a07f1 <S>` that only tracker, `hub/test/durations.json` and QA-brief paths changed since.
- **Part L, the live demo** (E1532D-20 to E1532D-32). One scratch project p1 with two fake hosts f1 and f2, driven through the `cland` CLI and the hub's frame protocol: a Codex item session on f1, a Codex session, an OpenCode session and a Claude Code session on f2; deliveries; a commit on f1 read in the territory; fetch, a leased push and three refused pushes through f1's git socket; `ready`; SSH-master kills, an agent kill and a 20 s hub stop with survival read after each; a revocation and the spoke's refusal; the attach command; a reboot with its exited sessions and vacated roles; the secret scan and cleanup. Then E1532D-40 reads freshness.

## Item

E-1532 (`kind: epic`, parent R-1530, labels `epic`, `v0.4`): The SSH transport, the host agent and git through the tunnel. A session can run on a remote Linux host and behave as a local one does: one hub-owned SSH connection per host with its own reconnect loop, four forwarded Unix sockets, the host agent `cland host serve`, git through `git daemon --inetd`, push on every ref move, attach, survival. Spec: `docs/spec/v0.4.md` §3.2, §3.3, §3.4, §3.12, §3.13. The demo is the item's `## Definition of done` (`task view E-1532 --json`, `.item.body`).

Seven stages, every plan member closed with exactly one first-parent landing on dev: "foundations" (QA scope none), "the tunnel" (QA clear, run `qa-tunnel2-2026-11-03-qa678-1` at `722f1ce5`), "the ssh Host and the remote spoke" (QA clear, `qa-s3-2026-11-03-qa678-1` at `8c9f569c`), "harnesses and git on hosts" (QA clear, `qa-s4-2026-11-04-qa678-1` at `eb1fe370`, A-16583), "push, attach and survival" (QA scope none), "relaunch elsewhere" (full-scope QA clear, `qa-s6-2026-11-06-qa678-1` at `cbd3433f`, A-17053), "Claude Code on hosts" (QA scope none, after-stage; T-1722 landed at `c8a74ac5`, T-1721 at `a43c0a0c`; its stage-occasion cover pair ran at `ca3a07f1`). These are reference only: E1532D-00 reads membership, states and landings from the tracker and Git at the run.

**Stage 7 and the C5 gap.** T-1722 (`found_by: qa`, regression of T-1601) closed the gap this brief's first draft found: `remoteHostLayout` set no `modDir`, so the Claude adapter refused every remote launch with `remote layout has no mod directory yet` and a CLI-started hub could not run Claude Code on any host. The remote layout now names `<code>/hub/mod/cland` (a host configuration may override it), and the registry's fake branch points `modDir` at the installed tree's `hub/mod/cland`; its C2 test (`claude-code-remote.test.ts`, `CLI-started hub launches a Claude item on a fake host with its mod bridge connected`) launches a Claude Code item session on a fake host through a CLI-started hub and reads the mod bridge acknowledgment. All three harnesses therefore run live in Part L. T-1721 changes `host-agent-restart.test.ts` timing only (the version-delivery variant's timeout and waits); its titles are unchanged. Whether a real host's code tree holds `hub/mod/cland` is E-1533's (T-1723), not this epic's.

**Criteria.** Judge each by its text in `task view E-1532 --json` at E1532D-00. At writing:

- C1. Each remote host has one hub-owned SSH master with the specified options, pinned host keys and the hub's own reconnect loop, and a killed master comes back with every forward.
- C2. Every host-side endpoint is a Unix socket in the agent-owned run directory, and no TCP forward exists.
- C3. Spokes on hosts connect through the hub's Unix-socket spoke edge with a per-host secret in a remote `hub.json`, and a revoked secret is refused.
- C4. The host agent runs every Host operation over `agent.sock`, is restarted by its supervisor within seconds, and sessions survive its restart.
- C5. Sessions of all three harnesses run on a host, and survive a hub restart and a tunnel loss with their rows re-found.
- C6. A host clones, fetches and pushes only through `git daemon --inetd` on its own socket, and a push to `dev`, to another host's branch or a deletion is refused.
- C7. A commit on a host reaches the territory without the session pushing, and `verify` and `ready` flush first.
- C8. `cland session attach` on a host session opens its own `ssh -t` running `cland host attach` with `stty susp undef`.
- C9. A rebooted host makes its sessions exited and vacates their roles, and a relaunch elsewhere recreates the worktree from the pushed branch.
- C10. ADR 0003 and ADR 0004 carry the amendments of spec §3.12.

If the ids or the text differ at the run, map by text and say so in the verdict.

## Probes that mislead

- Process cleanup uses the fixture-owned census (`$Q/pids`, plus processes naming `$Q`, the alias or this build's fakes); a machine-wide `pgrep claude`, `codex` or `opencode` counts the crew's real harnesses.
- **The live hub and workbench run the code of their last restart, not `S`.** Live sessions, the live `hub.db`, the live territory and live process rows are not evidence. p1, the build's files and tests, and the stage covers' logs are.
- **`session list` has no host field.** `HarnessProcessView` carries `cwd`; the rows read the host from the cwd prefix under each fake host's home (`onhost`, `probe home`).
- **Deliveries are read from `topic.history`.** The journal holds message metadata, never text. A `pong` found means the fake harness on the host answered through its own spoke over the forwarded `spoke.sock`.
- **Local pushes are not this run's git path.** E1532D-23 pushes from `worker`'s worktree on f1, whose clone has `origin` `git://cland/territory.git` and `core.gitProxy` set to f1's `run/git-proxy`, which relays to f1's `git.sock`, forwarded to the hub's per-host socket and its `git daemon --inetd` with `CLAND_PUSH_HOST=f1`. A push from `$Q` or p1 with `CLAND_PUSH_HOST` set (the stage-2 shape) exercises only the hook. The control push comes first: a refusal without a working control proves nothing.
- **The session's own ref-watch pushes too.** A commit in the worktree reaches the territory with no push by QA; QA's control push may find the branch already there (`Everything up-to-date`, exit 0).
- **`ready` here is the hub's automatic ready.** E1532D-24's flush is the same `useReadyAdmission` the session's own `task.edit` calls, entered through a reviewer-held verdict; the session-initiated path is E1532D-09's. Never write a review verdict from the CLI: a human or `cli:` writer never qualifies.
- **Revoke settles f2's sessions.** After E1532D-28 the `live` list still names `cx2`, `oc` and `cc`; no later row delivers to them (E1532D-29 and E1532D-30 read `worker` only).
- **The reboot census reads cwd.** The fake reboot kills the processes whose cwd lies under the host's home. The kit edit gives the supervisor and its agent that cwd; without it the old agent would survive the "reboot" with the old boot id. A `fake reboot requires native host owners` error means no such process was found.
- **The hub cannot bootstrap a supervisor on macOS** (no `setsid`); QA starts it with `probe svstart`, as every stage run did. A bootstrap attempt in `sv-*.log` or the hub log is expected noise.
- **OpenCode's loopback port.** The fake `ssh` refuses a host loopback port missing from `ports.json`; the all-ports map stands in for the tests' fixed `freePort` override. It does not change product code.
- **Claude Code's bridge receipt is the fake's job log, not a launch reply.** `ok 1` and a `running` row do not show the mod bridge: only `mod bridge bridged` in `$Q/fake-claude/jobs/<harnessId>.log`, written after the hub answered the bridge, does (T-1722's test reads the same line). `remote layout has no mod directory yet` now appears only for a layout that truly has none; on f2 it is a regression of T-1722, not a fixture fault.
- **Attach.** `cland session attach` prints the command and runs nothing; the printed command names the real `ssh` and is never run.
- **Two TAP logs stay private.** `spoke-unix-edge.test.ts` and `host-secret-admission.test.ts` print titles the publication scanner refuses (T-1665). Their logs live in `$Q/private` and are removed with `$Q`; only their check lines are evidence.
- **The covers' tree is the candidate tree** (tracker items excluded), not `git rev-parse <sha>^{tree}`; compare with `committedTree`, as `d14` does. `cland demo status --commit <sha>` judges `<sha>` against the live dev tip.
- **Exit 0 from the Node test runner with a name that matches nothing is not a pass:** confirm every listed name on an `ok` line (`tap.mjs`).
- Edit existing keys in initialized configs (`l21` edits `implementer.launch.writable_roots` through the build's `setRoleKey`); never add a second table.
- Speed criteria use measured wall times, never projections; timing allowances in `hub/test/durations.json` are not conditions here.
- Re-check helper and function names with grep at the tested build; renames happen. The kit's line ranges are pinned by the stage-4 blob; a different blob is a setup BLOCKED, never a reason to guess new ranges.
