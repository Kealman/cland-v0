# QA brief: E-612 Init: roots, the first commit, managed settings, categories

This brief is the Definition-of-done demo of epic E-612. QA runs it in the human's place, at a named `dev` commit, on a droplet through the demo lease (decisions D16 and D19 of v0.1 §4). Nothing in this DoD needs macOS. It has three parts.

- **Part G, local macOS (gates).** The build worktree at `S`, the children on `S`, the QA hold.
- **Part D, the droplet.** One demo lease at `S`. A scratch machine under `/tmp/qa612` with its own HOME (holding the hub's state directory `~/.local/state/cland`), XDG folders and Git configuration without an identity. On it QA plays the human with the `cland` CLI: `cland init` in every folder kind the DoD names, `cland update`, the managed settings, the categories, `cland` and `cland open` outside a project and before setup (a stand-in launcher as the tests use, and the real workbench headless), the version, and `cland release` against a local stand-in remote. Then the children's own test files, one at a time.
- **Part F, freshness and the verdict.**

Everything the run needs is in this file or in the files it names: whoever runs it cannot ask.

# E-612 QA scratch machine (qa/briefs/E-612.md). Every check sources this file from the delivered tree.

    XDG_CONFIG_HOME="$_home/.config" XDG_DATA_HOME="$_home/.local/share" \

// node snap.mjs <dir> <excluded>: every entry under dir except one subtree, sorted; files with sha256 and mtime
import { createHash } from 'node:crypto';
import { lstatSync, readdirSync, readFileSync, readlinkSync } from 'node:fs';
import { join, resolve } from 'node:path';
const [dir, except] = process.argv.slice(2);
const skip = resolve(except);
const out = [];
(function visit(path, rel) {
  for (const name of readdirSync(path).sort()) {
    const full = join(path, name), key = rel ? `${rel}/${name}` : name;

    const s = lstatSync(full);
    if (s.isSymbolicLink()) out.push(`L ${key} ${readlinkSync(full)}`);

})(resolve(dir), '');

EOF

## Gaps

What the DoD names that the merged code does not demonstrate as written. QA reports each as stated, not as a FAIL, unless a check above fails.

1. **`--dir` (C1).** The CLI has no `--dir` flag: `cland init [dir]` and `cland update [dir]` take the folder as a positional argument (`hub/src/cli/init.ts`), and `--dir` is refused with the usage line (R2e). C1 is judged on the positional form (I5, R1c, R2c, R2d, S3). Report as a low finding: the DoD's wording.
2. **"Moved" (C1).** The ledger is copied and reconciled into `~/.local/state/cland/spend.json`, and the legacy `~/.cland/executor/spend.json` stays byte-identical by design for older hubs (spend.ts: "retain the legacy file until an explicit cleanup after those hubs stop"). Nothing deletes it. L1 judges the move by the new ledger, the receipt and readers using the new path.
3. **When the move happens (C1).** Migration runs on the first locked ledger access (admission, lease sweep, a non-read-only `inspectSpend`), not at hub start; `cland executor status` reads both files without migrating (`readOnly`). No CLI command moves the ledger on demand, so L1 calls `inspectSpend` directly, as `executor-spend.test.ts` does, and E1 shows a hub reading the new path.
4. **Claude Code launch settings (C4).** No real Claude Code is launched in this demo. That launches carry the key only where the project lacks it is proven by `claude-code-environment.test.ts` (T8) through the adapter's recorded CLI boundary. That `.claude/settings.local.json` overrides the project file inside Claude Code is Claude Code's behaviour; the demo shows cland leaves the file byte-identical (S3) and the tests show the launch omits the key then (T8).
5. **"Clean `dev`" for a repository with history (C3).** Init makes no commit in a clone (`master`, `trunk`): the root is on `dev` with no tracked change, and cland's files are untracked (I4). The DoD's "first commit … clean `dev`" applies to folders without a commit (I1–I3). Report I4's untracked list as information.
6. **Bare `cland` (C5).** `cland` with no command opens the workbench only when stdin and stdout are terminals; through a pipe it prints the help and exits 0 (`hub/bin/cland.ts`). O2 proves the DoD's line with a pseudo-terminal (`script`), and records the pipe behaviour as information.
7. **Setup's mark (C5).** `cland setup` is not built (out of this epic). O3b writes setup's mark (`CHOSEN` from `hub/src/roles/editor.ts`) with a script to show the hint disappears.

## Pitfalls

- **Only through the library.** Every `cland` and `git` call of Part D goes through `c`, `g` or `run` (env -i, scratch HOME). Never run `cland init`, `update`, `open`, `hub` or `release` in the delivered tree, the root or `$W`.
- **Order matters.** R2 needs I1's project; I1b, S1–S3, K, O3a, O4, O3b, V2 need `<P1>`; K must stop its hub before O3a (O3a shows open starting it); V2 reads I1b's JSON, needs O3a's hub and then stops it, so E1's snapshots see no running hub; E2 and E3 need E1's hub. Run the checks in the Procedure's order.
- **UTC midnight.** The seeded ledger entries are dated by `date -u` in D2; E1's and L1's `spent` values assume the checks run the same UTC day as D2. If the day changed, rerun D2 and the checks from R1 (a new run id is not needed: D2 resets the machine).
- **Stand-in safety.** E2 and E3 stop with `UNSAFE` unless `github` is the stand-in. Never point it elsewhere.
- **One lease.** Never run `demo start` twice. Record D lines before `demo stop`.
- **Never work around a refusal.** A refused demo control or verdict is evidence: record its exact text.
- **Process reads print counts, never command lines or environments.**
- `qa-record.sh` takes `E-612`. The verdict goes on `E-612`.
