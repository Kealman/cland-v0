# QA brief: E-420 Release v0.2.0 from the item (Definition of done)

This brief is the Definition-of-done demo of epic E-420, **up to the dry run**. QA runs it in the human's place (D16 and D19 of v0.1 §4; spec v0.2 §4: no separate human acceptance pass), at the full `dev` SHA that the request names, and plays the human's part as the DoD says: through the `cland` CLI (every browser sign-in link comes from `cland web --no-open`, run as the scratch project's human), headless Chromium (the suite's Chrome Headless Shell: a desktop context at 1440x900 and a phone context at 390x844 with touch and the mobile flag, each with its own cookie) and a headless Neovim workbench. The epic closes on QA's clear verdict; the Coordinator then shows the dry run in an ask and releases from its own shell (the `release` skill). QA's post-release check of the tag is a **separate request on R-377** (Procedure, "After the release") and is not part of this verdict. The run has three parts.

- **Part D, the droplet.** One demo lease at the requested commit, through `cland demo` only. On it QA installs the helpers below, builds the sealed environment and the web bundle, and runs three walks: the integrated pass of the DoD's demo paragraph, with a desktop context, a phone context and a headless Neovim workbench on one scratch hub at once (walk 1: a relayed Codex approval answered on the phone and folding in the desktop Inbox and in Neovim's, a second one approved from the session's drawer, one ask answered by both contexts at once and read as one outcome, a topic read in Neovim reading as read in both contexts, the phone resuming after a hub restart); a fresh clone followed by `web/README.md` to a signed-in browser (walk 2); R-377's item dry run reproduced in a scratch release project (walk 3). It then runs the named test files that support C2, C3 and C4. Once every droplet row and the captures are recorded, QA releases the lease at once (E420D-13).
- **Part L, local macOS.** The read-only live reads: the hold, the epic and its plan, R-377's open items and every other epic's closing QA verdict (C1); the version, R-377's `## Notes` at `S` and the Coordinator's root dry-run attempt (C4); the docs (C3); the brief's lint; the Coordinator's two covers at `S`, cited and never run by QA (C5); and, immediately before the verdict, the freeze and freshness check.
- **Fallback.** If the demo start is refused for lack of a remote slot or spend budget, every Part D row runs on this Mac in the worktree, unchanged, after `quiet`. Part L is local either way.

**Safety in one line.** QA never runs `cland release` without `--dry-run` anywhere, never runs any `cland release` on the live hub (not even `--dry-run`: GAP-1), never pushes to any remote, runs no full suite and no occasion, opens no real browser and touches no real-HOME harness configuration. Every scratch command runs sealed in a scratch project of its own.

Everything the run needs is in this file or in the files it names: whoever runs it cannot ask. Commands are for bash (zsh reads `$S:q` as a modifier, and sourcing the sealed `env.sh` from zsh aborts): start `bash` first. Binary formats are decoded with Node, never with `od` or `awk` (none is needed here: the screenshots are evidence, not facts).
