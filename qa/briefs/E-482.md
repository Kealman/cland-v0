# QA brief: E-482 Flake sweep: the load-sensitive tests found in v0.1.2

This brief is the Definition-of-done demo of epic E-482. QA runs it in the human's place, at a named `dev` commit, partly on a droplet through the demo lease (decisions D16 and D19 of v0.1 §4). It reuses the conventions of the E-676 brief. It has three parts.

- **Part D, the droplet.** One demo lease at the requested commit. On it, every test file the epic's children fixed: once each, serially and quiet (C1, "once on a Linux droplet"); then five rounds of the whole set with four files running at once (C1, "5/5 beside a full run", the load the Coordinator's evidence rule names); then the reruns of any file that failed.
- **Part R, records, read-only.** The set of fixed files and the children behind them, the closure and verification state of all children (C1, C2), a scan of every child's landing for weakened assertions and widened time bounds with the recorded reasons (C2), and the files' presence in the newest green droplet integrated run (C1).
- **Part L, local macOS.** Reads only. QA runs no test file on the Mac (see "What cannot be demonstrated here").

Everything the run needs is in this file or in the files it names: whoever runs it cannot ask.

## Changes since the last run

- D1: Neovim is resolved with `node nvim/bin/nvim-path.ts` and its `--version` compared with `nvim/NVIM_VERSION`, not `nvim --version` on PATH.
- Commands: `"$S:qa/..."` is now `"${S}:qa/..."` (zsh reads `$S:q` as a modifier); the brief tells QA to run its blocks with bash.
- Recorder surfaces: `qa-record.sh note` now uses `hub-api` (accepted surface) everywhere; the platform goes in the method text.
- INT_LOG replaced by INT_LOG_LINUX / INT_LOG_MAC: R3 reads the Coordinator's stage covers at S instead of searching for a log; QA submits no verify.
- `quiet()` fails closed: any local holder (not only coord), waits up to 10 minutes, returns 1; the local checks (F1, R2) are then recorded BLOCKED.
- Build: same-SHA prerequisite for all nine demos.
- D3/D4/D5 scripts: the result of a file run is its exit code (one complete log per run in /tmp, never overwritten); `ℹ` lines are no longer parsed.
- Collection of the complete per-run logs and exit codes from the lease before demo stop.

**Block R2 (C2).** Scans every child's landing diff on test files for four signals: fewer assertion-like lines removed than added (`asserts a->b`), fewer `test(` / `it(` / `describe(` lines (`tests a->b`), an added `skip` or `todo` on a test line, and the largest number on a timeout-like line going up (`bound x->y`, any unit: a 15 changing to 20000 may be seconds to milliseconds). It is a net, not a judge: a candidate is not a finding until you have read it.

```sh
cat > $EV/R2-scan.cjs <<'JS'
const { execFileSync } = require('child_process'); const fs = require('fs');
const R = process.env.R, S = process.env.S, ids = process.env.IDS.trim().split(/\s+/);
const git = (...a) => execFileSync('git', ['-C', R, ...a], { encoding: 'utf8', maxBuffer: 1 << 28 });

const TT = /^\s*(test|it|describe)(\.\w+)?\(/, SK = /\b(skip|todo)\b/, num = s => (s.match(/\d[\d_.]*/g) || []).map(x => parseFloat(x.replace(/_/g, '')) || 0);

let landings = 0; const out = [];

  if (git('log', '-1', '--format=%s', sha).startsWith('Tracker:')) continue; landings++;
```

How to judge a candidate. Open the commit (`git -C $W show <sha> -- <file>`) and the child's record: its task file, `cl task view <id> --json` comments (the Implementer's evidence and the Reviewer's verdict text), and any artifact they cite.

- A **recorded reason** is a statement by the Implementer or the Reviewer, made before the merge, that names the changed assertion or bound and says why (for example "the assertion's meaning is kept: the same value is now read after the observed boundary", "the 15 s bound is a per-wait deadline, unchanged in the assertion", "the unit is milliseconds"). A bare "bounded observation" in a verdict, or a commit message with no body, is not a reason for a widened bound.

## Pitfalls

- **One worktree.** `$W` is the build: never switch, edit or commit there. This brief makes no other worktree and no branch.
- **The lease clock.** D3 and D4 are long. Poll, do not hold a `demo exec` open. Check the deadline before each D4 round and stop at a round boundary rather than running into it.
- **Quiet means quiet.** Do not run D3 while anything else runs on the lease: D2's scripts, the load sampler of an earlier step, a left-over `xargs`. `dx sh -c 'pgrep -fc "[q]a-e482-one|[n]ode --test" || true'` prints `0` before D3 and before each round's start.
- **Parallel files share a machine.** D4 runs four files at once on purpose. A failure there that does not recur in D5's serial rerun and recurs in the load rerun is a load flake of that file: report it with its child, do not hide it.
- **Process reads print counts, never command lines or environments.** The scripts print file names, exit codes and `ℹ` counts.
- **Commands on the droplet** are argument vectors: `sh -c '<script>'`, with `$f`, `$r` and `$l` inside the single quotes (or escaped in the double-quoted D2 block) so the droplet's shell expands them.
- **Never work around a refusal.** A refused demo control or verdict is evidence: record its exact text.
- `qa-record.sh` takes `E-482`. The verdict goes on `E-482`.
