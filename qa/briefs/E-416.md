## Probes that mislead

- Process cleanup probes use a fixture-owned pid/process-group census, registered at launch and checked through exit; a machine-wide `pgrep` counts other sessions too. Here: each Web fixture's `Web fixture census: browser group <pid>; before <n>; after 0; scratch hub stopped` line.
- Edit existing keys in initialized configs, list standalone-test build prerequisites, enumerate regular files only for file probes, and identify events by seq/id. - Exact tracker copies replace the initialized tracker directory after its writers stop; copy the committed directory whole, dotfiles included, and compare that same file set. Here: the walkthrough copies `$W/.cland/tasks` (the tested build's, never the root's live edits) before the scratch hub starts; `DOD-00` prints the count it read.

- Frame logs count frames the page sends. A `task.list` with `ids` is a by-id summary page (closed cards, link targets, plan members), not a body request; only `task.view` is a body request, and the card sends one only for `Agents’ text` or an opened `Criteria` block.

- The scratch hub has run no suite: `cland verify none` on the demo card is expected, not a finding ("Shown in part").
- File-change probes use isolation; mtime alone is confounded by live sessions rewriting the same file.
- A "ran" marker grep excludes the configuration echo line.
- Successful droplet prepare logs are in the run's `delivery.log`, not the suite log.
- Speed criteria use measured wall times, never projections; duration and budget lines (the dated Web allowances, owner E-880) are report-only.

- "No skip" names platform-only cases and where they are covered: Part D's Web files need Chrome Headless Shell (the droplet snapshot has it) and E416-D08 the pinned Neovim; a skipped file, `Web unavailable` or "pinned Neovim missing" is BLOCKED, never PASS.
