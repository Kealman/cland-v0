## Probes that mislead

- **The control's root is the project root, not a separate fake-host directory.** `host-tunnel-control.ts <root>` reads `<root>/.cland/config.toml` and `<root>/.cland/hub.db` and requires `realpath(CLAND_FAKE_HOST_ROOT)` to equal `realpath(<root>)`; with stage 1's separate `$Q/fh` it refuses every host. Here `$Q/fh` links to `$Q/p1`; pass `$Q/p1`. A refusal naming `owned fake host root` on the outage row is a setup fault, not a product failure.
- **An outage is read on a subscribed connection.** A plain connect read is a snapshot of the cached projection; only subscribed or numbered-delta peers get replacements. `ho.mjs` subscribes before it runs the control and measures from the control's launch to the first pushed frame with the alert; `hs.mjs connect` after it only confirms the final state.
- **The outage alert is not the `unreachable` state** (carried). The alert appears at tunnel loss while the provision still reads `ready`; the 3-minute `unreachable` state and General's line are unchanged.
- **The 3000 ms bound includes control startup.** The native test's `OUTAGE_MS` covers launching the control, the master's exit, the carrier's status, `HostHealth` and the one-second coalescing; the recovery wait is setup-style in both the native test and E1537S2-84.
- **The hosts view is the Hosts fold's body.** It mounts only while the fold is open, so folding is "closing the view" (T-1825 C3) and discards an open confirmation; a missing view while the fold is closed is correct.
- **The view's login lines come from `login.list`, not from the frame.** `hosts.state` carries only per-harness counts; the view refetches `login.list` on every pools replacement and, since T-1827, on every change of the connection's sign-in index; Remove, Snapshot, Add and Sign in again refetch it after the hub's result. - **`host.providers` has no CLI command at this build.** It is pull-only and local-only (human CLI or Neovim socket clients); `frame.mjs` sends it as the CLI client. Doctor and setup are its stage-3 consumers.
- **The token sentinel is never written down.** E1537S2-90 reads it from the test source and prints only its length; a brief, record or artifact that contains it is itself a finding.
