## Scripts

**S1. The log comparison (R4, R5).** Every runner log has `suite timing {"file":…,"name":…,"seconds":…}` lines, in the old A-2714 log and the new ones alike. The script keys a test by file and name, keeps only tests present exactly once in both logs, drops whole-file entries (name ending in `.test.ts`), and sums seconds. Write it once to `$EV/cmp.mjs`.

```sh
cat > $EV/cmp.mjs <<'EOF'
// usage: node cmp.mjs BEFORE_LOG AFTER_LOG [--hub] [--files a.test.ts,b.test.ts] [--per-file]
import { readFileSync } from 'node:fs';
const [before, after, ...flags] = process.argv.slice(2);
const hub = flags.includes('--hub');
const fi = flags.indexOf('--files');
const files = fi >= 0 ? new Set(flags[fi + 1].split(',').map(f => f.trim()).filter(Boolean)) : null;
const base = f => f.replace(/^.*\/(hub|nvim)\//, '$1/');
function load(path) {
  const m = new Map(); const dup = new Set();
  for (const line of readFileSync(path, 'utf8').split('\n')) {
    const i = line.indexOf('suite timing {'); if (i < 0) continue;
    let r; try { r = JSON.parse(line.slice(i + 13)); } catch { continue; }
    const file = base(r.file); if (r.name.endsWith('.test.ts')) continue;
    if (hub && !file.startsWith('hub/')) continue;
    if (files && !files.has(file.split('/').pop())) continue;
    const key = file + ' :: ' + r.name;
    if (m.has(key)) dup.add(key); m.set(key, r.seconds);
  }
  for (const k of dup) m.delete(k);
  return m;
}
const b = load(before), a = load(after);
const common = [...b.keys()].filter(k => a.has(k));
const sum = (m, ks) => ks.reduce((s, k) => s + m.get(k), 0);
const sb = sum(b, common), sa = sum(a, common);
console.log(`tests before ${b.size}, after ${a.size}, common ${common.length}`);
console.log(`common test-seconds before ${sb.toFixed(2)}, after ${sa.toFixed(2)}, change ${(100 * (sa - sb) / sb).toFixed(1)} %  (negative = faster)`);
if (flags.includes('--per-file')) {
  const per = new Map();
  for (const k of common) { const f = k.split(' :: ')[0]; const p = per.get(f) ?? [0, 0]; p[0] += b.get(k); p[1] += a.get(k); per.set(f, p); }
  for (const [f, [x, y]] of [...per].sort()) console.log(`${f}  ${x.toFixed(2)} -> ${y.toFixed(2)}  ${(100 * (y - x) / x).toFixed(1)} %`);
}
EOF
```

**S2. Recent task-run durations (R3).**

```sh
cat > $EV/runs.mjs <<'EOF'
// usage: node runs.mjs ARTIFACT_DIR [count]
import { readdirSync, readFileSync } from 'node:fs';
import { join } from 'node:path';
const [dir, n = '10'] = process.argv.slice(2);
const logs = readdirSync(dir).filter(f => /^A-\d+-suite-[0-9a-f-]{36}-auto-at-[0-9a-f]+\.log$/.test(f)).sort((x, y) => parseInt(y.slice(2)) - parseInt(x.slice(2)));
const rows = [];
for (const f of logs) {
  const L = readFileSync(join(dir, f), 'utf8').split('\n');
  const d = L.find(l => l.startsWith('suite duration ')); if (!d) continue;
  const mode = /mode ([a-z-]+)/.exec(d)?.[1]; const sec = parseFloat(/suite duration ([0-9.]+)s/.exec(d)[1]);
  const remote = L.some(l => /^typecheck: (droplet|host gate)/.test(l)) || L.some(l => l.includes('/home/runner/'));
  if (mode !== 'hub-selected') continue;
  rows.push({ id: f.split('-').slice(0, 2).join('-'), mode, sec, remote, exit: (L.find(l => l.startsWith('Finished:')) ?? '').trim() });
  if (rows.length >= Number(n)) break;
}
for (const r of rows) console.log(`${r.id}  ${r.mode}  ${r.sec.toFixed(1)} s  ${(r.sec / 60).toFixed(1)} min  ${r.remote ? 'droplet' : 'local'}  ${r.exit}`);
const s = rows.map(r => r.sec).sort((a, b) => a - b);
if (s.length) console.log(`n ${s.length}  median ${(s[Math.floor((s.length - 1) / 2)] / 60).toFixed(1)} min  min ${(s[0] / 60).toFixed(1)}  max ${(s.at(-1) / 60).toFixed(1)}  under 5 min: ${s.filter(x => x < 300).length}`);
EOF
```

## Pitfalls

- **Identity.** QA's own commands (`cl`) act as QA on the live hub. Every droplet command runs under the lease; none of them touches the live hub.
- **The census is the droplet's, not the Mac's.** `spawn-census.mjs run` runs `npm test -- --all`, which takes a machine-wide lock and a full load. It runs only inside `cland demo exec E-578`. Never run it, `npm test` or `npm run test:nvim` on the Mac.
- **Different machines are different measures.** Mac and droplet numbers are never compared with each other (R4, R5 compare Mac logs; D2 compares to the Mac count only for the bar of 600). Name the platform of every number.
- **Common tests only.** R4 and R5 compare tests present once in both logs; a changed test name drops out of both sides. The note says how many were common.
- **Droplet exec quoting.** Commands are argument vectors: `sh -c '<script>'`, with `$PWD` inside the single quotes so the droplet's shell expands it. A quoting error that is not a product result is INCONCLUSIVE with the exact message, then fixed in the same lease.
- **The drafter did not run these commands.** The scripts and the artifact patterns are written from the repository at the time of writing (the `suite timing` line format, `A-2714`, `A-4088`, `A-5702`). If an artifact id or a log shape differs at `S`, report a brief defect and use the nearest equivalent; do not mark the product failed for it.
- **One lease.** Never run `demo start` twice. Record D lines before `demo stop`.
- **Never work around a refusal.** A refused demo control or verdict is evidence: record its exact text.
- `qa-record.sh` takes `E-578`. The verdict goes on `E-578`.

## Procedure

1. Choose a run id, `qa-<date>-<n>`, and set the Environment (including S1 and S2). Announce START in the request's topic, naming `S`. `dev` is not frozen: D5 decides.
2. Run, in order, recording each with `qa-record.sh` under `.cland/qa/E-578/<run>/` of the root:
   1. G0, G1 and G2. If any is not PASS, stop: the run is BLOCKED.
   2. Part D: D0, D1, then D2 (if the lease has the time), D3 and D4 one at a time on the one lease. Then D5, and D6 last of Part D.
   3. Part L: `quiet`, then L1. Part L may run beside D2.
   4. Part R: R1 to R8 (X1 only on the request's written word).
3. Fix nothing. A failure is a finding: write down the check id, the command and what it showed.
4. The verdict is `clear` only when every check in scope is PASS or PASS (D66). It opens with the table of every speed number (the target, the measured value, the run ids, and whether it passed outright or under D66) and says that D66 names E-678 and was applied to E-578 on the requester's instruction. Otherwise it is `not clear`, naming each check that was FAIL, BLOCKED or INCONCLUSIVE.
5. If a step fails, keep what is already written and finish from there. Never rerun a check under the same run id; a D3 or D4 rerun is the flaky rule's one rerun, in the same lease, reported beside the first result.
6. Before the verdict, run D5's freshness read again if `dev` moved since D5. Publish the evidence with `artifact.create` (kind `note`: the check table; the speed-number table; the lease, executor, commit, lifetime and cost; which checks ran where; the findings; the replay and duration results that T-394 C5–C7 owed) **in the epic's topic where the request was delivered**, and name its id in the verdict text.
7. Write one verdict on E-578 from `$W`: `cl task comment E-578 "<text>" --verdict qa --result clear --run $RUN --commit $S --verified all`. A not-clear verdict carries only `failed` (one `{ criterion, note }` per failed criterion, single-line notes) and names in its text the criteria that passed. The text opens with the check table, then the findings ranked high, medium and low. If the hub refuses the verdict as `qa-stale`, keep the evidence and report BLOCKED. Any other refusal: fix its cause and write only the verdict again with the same run.
8. Release the hold if the verdict did not: `cl task hold E-578 --release`. Remove the build worktree: `git -C $R worktree remove $W`.
9. Report with `send` kind `report` to `lead E-578` in the request's topic: first line `qa clear E-578` or `qa not clear E-578`, then the failed checks, the lease and its cost. Report any find outside the epic (for example the README line that still says four workers) as a bug found aside, with its evidence.
