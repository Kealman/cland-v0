## Goal

v0.1.4 is cland on a new project: a deterministic `cland init`, the interactive `cland setup` (harnesses, accounts, the favourite harness, the Aide launched in the workbench), the onboarding the Aide leads from a skill on an empty or an existing project, the curated skill set edited in place, and the welcome artifact. cland itself is assumed installed from the checkout on the human's machine; the one-command install on a fresh machine is deferred (Q-592's research stands for later). The way is charted on the map "cland on a new project" (M-591); spec `docs/spec/v0.1.4.md` and the epics follow it.

It also takes what the human carried over from v0.1.3 on 2026-10-16 (ask 396ec11a, answer 4c507896): E-482's remaining known flakes, E-424's OpenCode hygiene items, and the E-387 and E-425 follow-ups, T-575, T-520, T-475 and T-379. It sits before v0.2 (R-377).

The goal: a newcomer gets from cland's checkout to a crew at work on an empty or an existing project by answering questions, and the crew's tests run at the right tier through a hub-owned merge queue.

What the human can now do, by epic:

- **E-611 The Aide's reach and the settings commands.** On the human's word, the Aide launches, stops and resumes sessions of any role, the Coordinator included, with its tool or `cland` in its shell. It imports GitHub issues with `task.import` and publishes `dev` with `cland push`, and every other role keeps its refusals. An existing `roles.toml` gains the new Aide tools once, at the first hub start of 0.1.4. `permissions = "auto"` launches Claude Code with `--permission-mode auto` and is the template default; `skip` is written only on the human's choice. `cland role launch`, `cland config set` and `cland models <harness>` replace hand edits of `roles.toml` and `config.toml`, and refuse values the hub cannot read. An unpinned Claude Code launch no longer gets an empty profile (T-603), and rule titles are kept whole and can be edited (T-608). QA clear: qa-2026-10-19-1 (A-5810).
- **E-612 Init: roots, the first commit, managed settings, categories.** `cland init` serves only the folder it is given and never takes HOME as a root. The hub's state lives in `~/.local/state/cland`, and the spend ledger moved there. An empty folder, a repository without commits and a folder without Git get a first commit of cland's files only, as `cland <cland@local>` when Git has no identity. Init accepts any default branch, seeds the four categories, refuses a shallow clone with a hint and ends with `next: cland setup`. `.claude/settings.json` holds the managed `bgIsolation` key, so background Claude Code sessions can edit the root. The root `package.json` version is cland's only version, and `cland release` refuses a different one with `release-version`. QA clear: qa-2026-10-19-1 (A-5824).
- **E-613 Setup: the guided step ending in the workbench.** `cland setup` runs eight steps in order, one line each: the project, the harnesses, the logins, the accounts, the favourite harness, trust, the hub and the Aide. A missing harness is installed on yes, a declined install is remembered until `--install`, and the accounts question defaults to No. Trust is granted for every installed harness without a question. QA proved it on fake harnesses and on this Mac's Claude Code 2.1.304, Codex 0.163.0 and OpenCode 2.0.24 under scratch profiles. Setup ends with `aide-1` running the onboarding brief in the centre of the workbench, and a second run reports `ok` throughout. Without a terminal it prints each open step with its command and exits 1. `cland doctor` requires only the harnesses the roles use, shows versions without a verdict and no longer counts OpenCode's environment keys as a login. QA clear: qa-2026-10-20-2 (A-7033).
- **E-614 Verification for any stack.** `cland verify` runs the project's own `[verification]` commands from `config.toml`: `check` and `test`, locally and on a droplet. The host gate runs `check`, and a droplet runs `prepare` where it ran `npm ci` and the Neovim pin. `cland config set verification.<key>` sets them. QA verified a Python scratch project on the Mac and on a droplet, and a planted failing test turned each run red with its assertion. Coverage selection stays with cland's own node commands. In this repository the replay over 40 landings selected 7 with zero misses. QA clear: qa-2026-10-20-1 (A-7044).
- **E-615 The curated skill set and cland update.** `.agents/skills/` holds 15 vendored skills and cland's own five, and 23 skills are gone, with `skills-lock.json` and `skills/PATCHES.md`. Each kept skill carries its origin commit, the MIT notice and one line of changes in its own header. Codex now lists implement, to-spec, to-tickets, triage and wayfinder. `cland update` keeps a SHA-256 per file: it refreshes an untouched skill and keeps an edited one, reporting it as "edited in the project". A dropped skill the project edited is handed to the project. QA clear: qa-2026-10-19-1 (A-5873).
- **E-616 The onboarding skill and the newcomer's first page.** `cland init` provisions the `onboarding` skill. With it, the Aide records the human's role and decisions as rules and files a first release, or a map when there is fog. On an existing project it imports the open issues and files "what next". It records the stack's verification commands and the crew, writes a welcome note in General, commits and pushes on the human's ok, and launches the Coordinator. On request it gives the eight-stage tour in the human's language. `hub/README.md` opens with the newcomer's first page, and GLOSSARY.md defines Setup, Onboarding, Tour and Welcome note. C2 to C6 were accepted on a fake-harness replay of the Aide's acts plus a check of the skill text (D71); a live Aide run is the human's call after the release. QA clear: qa-2026-10-20-qa2-2 (A-7032).
- **E-676 Tests at the right level, part 1.** Every test file has a tier in `hub/test/tiers.json`: 405 files, with 65 in T1, 150 in T2, 180 in T3 and 10 in T4. `shards.json` is gone. At verify and at merge admission, a test lint refuses a new T3 file without a lifecycle header, a new numeric sleep and a new `startDaemon` call. Each run reports per-tier lines, the tier share, the lint summary and the budget lines, and `cland verify --dry-run` prints the plan without queuing anything. The hub gained a `FakeClock`, an in-process fake adapter for the three harnesses and an in-process spoke. `heartbeat.test.ts` fell from 25.7 s to at most 1.58 s per run. An Implementer's `cland verify all` is refused with `verify-all-reserved`. QA clear: qa-2026-10-18-6 (A-5593), carrying the full run qa-2026-10-18-5 (A-5589). Runs 1 and 3 were not clear, on a truncated delivered result (T-800) and on admission timeouts under load.
- **E-677 Tests at the right level, part 2.** The heaviest files moved to T1 and T2 by class. Each harness keeps one real-binary contract file: Claude Code 23 s, Codex 25 s and OpenCode 32 s on the demo droplet. Eleven T3 scenarios of 1–14 s each replace the integration files they cover. T1–T3 manifest seconds fell from 5281 s to 2518.09 s, under the 3600 s target, and no T2 Neovim file reaches a `hub/src` runtime module. The T1+T2 share is 16.2 % against 60 %, and T3 holds 2109.78 s against 1800 s. Both count as met under D71. The T1 and T2 phases took 485.66 s and 661.42 s on two c-8 shards, against 480 s, and count as met under D74. QA clear: qa-20261020-3d (A-7037).
- **E-678 Merge queue.** `cland merge` puts a reviewed head into a hub-owned queue. The hub batches up to four heads (D64), lands a green batch and bisects a red one by failing file with `merge-bisected`. A task verify runs T0, T1 and the selected T2 tests. Stage, epic and release runs cover T1–T4 on both platforms, and a nightly soak runs within the daily cap. Since D67, a batch runs T1 in about 2 minutes. T3 runs on `dev` every 2 hours, in the soak and as the release gate, and a red periodic run finds the merge that broke it. Per-tier `[verification]` commands give any stack this model. Manual covers are retired: of 187 commits on `dev` since T-713 went live, 118 landed from green batches, 6 from resolved reruns, 57 were tracker or docs only, and 6 were recorded exceptions. Measured against the targets: a task-run median of 12.9 min (8 min), 2.31 runs per merge (1.6), a batch median of 40.1 s and $0.009 per merge. QA clear: qa-2026-10-20-1 (A-7035).
- **E-578 Test speed: structural, part 2.** A full run starts 176 hub daemons, from 743 in v0.1.3, under the 600 target. Hub test time on the Mac fell 33.9 % over 1102 common tests (1585.26 s to 1047.11 s), against a 15 % target. Coverage-selected task suites take a median of 2.0 min over ten runs, 8 of them under 5 minutes. The replay of 40 landings selected 7 with zero misses. The two-shard stage wall is 1615.43 s against 600 s, and T-393's 20 files are 2.1 % faster against 20 %. Droplet workers are 2 on c-8, from the T-654 to T-656 experiments, and the local and c-16 rows were not measured. C2 to C6 count as met under D71. QA clear: qa-20261020-3f (A-7053).
- **E-424 OpenCode v2 hygiene.** cland's OpenCode sessions keep their own database (T-296, in v0.1.3), and QA reran the P3 proof against OpenCode 2.0.24. Launch waits for the server's readiness on a port cland chose, and a rejected approval is reported as a rejection while the session stays alive. The `roles.toml` policy (approval, sandbox, permissions, the item rule, effort) maps onto OpenCode session rules, as the table in `hub/README.md` says, and `provider/model#variant` is parsed. Injects carry idempotent `msg_` ids, and child sessions report their model and usage to the parent. The doctor warns that the free model may train on the code and that OpenCode has no OS sandbox. A session moved out of its worktree raises a warn-level event to its lead. The codemode experiment (8/10 against 7/10) kept the default, and the instructions experiment was inconclusive (T-619). Version checks are informational (the human's amendment, Q-599). QA clear: qa-20261020-3c (A-7029).
- **E-482 Flake sweep.** 68 more load-sensitive tests were fixed in this build, 110 in all with v0.1.3's 42, including the nine carried flakes. Each one now waits on the state it asserts, never on wall time. The analysis A-4004 put the cause on load: 0 % red below a peak load of 6, 62 % at 10–15. A known flake still runs and is reported but no longer fails the run (T-657). Task runs wait for a droplet instead of falling back to the Mac (T-658). A merge-time lint refuses new wall-clock waits (T-660). The first demo run (qa-2026-10-20-qa2-3) was not clear: the handover-process test hung on cleanup under load, which T-935 fixed. The fresh run passed all 94 fixed files serially and in five rounds of four at once (564 file runs, zero failures), and its C2 audit explained all 11 candidates over 104 landings. QA clear: qa-2026-10-20-qa2-4 (A-7176).
- **E-579 Hub hygiene, part 2.** A tracker-only commit on `dev` no longer cancels or invalidates an integrated run (T-379), and a rulebook commit keeps the run too. While the Coordinator's cover holds the slot, the test harness refuses to start a fixture hub (T-475). The first demo run (qa-20261020-3e) was not clear: the host gate kept its own copy of the exclusion list, and `docs/agents/tests.md` left out the rulebook exclusion. T-933 now takes the exclusions from one shared definition, and the docs name the rulebook. QA clear: qa-20261020-3g (A-7115).
