## Summary

A hub module verifies WebAuthn registration (attestation `none`) and assertion by hand on `node:crypto`, with no dependency: it parses CBOR, authenticator data and COSE keys, and checks challenge, origin, RP ID hash, flags, signature and sign counter. It is a deliberate deep module, landed alone because its correctness is the security boundary that L11 builds on (the epic's constraint: an unsafe check leads to an ask about a dependency, never a weaker check).

Hot files: new `hub/src/hub/webauthn.ts` (with a minimal CBOR reader) and its test file. No shared file.

## Acceptance criteria

- [ ] C1. A registration response with attestation format `none` yields the credential id and a public key for ES256 and Ed25519 (and RS256 if supported), from fixtures signed with keys generated by `node:crypto` in the test.
- [ ] C2. An assertion verifies only when the type, challenge, origin, RP ID hash, user-present flag, user-verified flag (when required) and signature over authenticator data plus the client-data hash all match.
- [ ] C3. A tampered byte in each signed part, a wrong challenge, a foreign origin, a foreign RP ID and a non-increasing non-zero sign counter are each refused with a distinct reason.
- [ ] C4. Malformed CBOR (truncated, indefinite length, oversized, nested past a fixed depth) and unsupported COSE algorithms are refused without throwing out of the module.
- [ ] C5. The module imports only `node:` built-ins, and `package.json` and the lockfile are unchanged.
