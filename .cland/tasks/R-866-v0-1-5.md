The debt-sweep release after v0.1.4. On 2026-10-20 the human moved the post-release sweep E-952 here and asked for it to ship as v0.1.5 when it closes (D78), and to be released without a separate ask once the gates are green (D79).

## Notes

Scope: E-952, the debt sweep D76 set up, plus what the rule batch, the periodic dev T3 and the merges themselves found on the way (`docs/spec/v0.1.4.md` §5, D76 to D79). Version 0.1.5 is R-866's recorded version (D78). The sweep ran on 2026-10-20 from 09:4xZ under the Coordinator `coord`. Implementers and Reviewers ran on Codex gpt-6.1-sol and the Coordinator on claude-opus-5-5. Every task landed through the hub's merge queue in T1 batches (D67). The periodic dev T3 at 224d45cc caught nine T3 regressions from two of the sweep's own fixes, and its culprit search confirmed them. T-964 and T-965 fixed them before the release (D77). The first two pairs of stage covers then found three more. T-962's sealed child launches broke five tests on both platforms, so T-970 reverted it; its fixed re-land is T-971, under v0.2. T-807's fixture ownership put a synchronous call on the tracker's native boundary (T-972) and broke the read-only Neovim QA case on macOS (T-974). The fourth pair of covers, at 9ae9a20b, is green on Linux (3311 pass, 0 fail) and macOS (3319 pass, 0 fail). The human adopted the v0.1.4 rule batch (A-7281). Rule 9 now covers waiting for the durable receipt of the boundary a test asserts. Rules 15 to 17 are new: sealed real-machine work, docs in the same item, and evidence that states what actually ran. Rule 14 is retired in favour of `cland publish` after an ask.

What changes for the human and the crew:

- **Reviews and QA are no longer stranded.** A stale uncertain notice in a verifier's queue no longer makes an idle Reviewer look busy, so queued review requests reach it (T-587). A `send` with a single-string `to` reaches its recipient, and a malformed one gets a clear error, never a refusal as a send to the human (T-966). A claimant whose verdicts are clear but whose criteria lack done marks is told which marks are missing (T-958). `cland topic create` exists for shell-only sessions (T-951).
- **Verification and the merge queue.** A verify that fell back to the local machine moves to a remote slot when one frees, across restarts too (T-561). A release run is never satisfied by a cached run of another occasion or executor, and the cache notice names the original run (T-950). The periodic dev T3 starts only when the tested tree changed, not on a tracker commit (T-949). A broken spend ledger no longer hides a sharded close run's result (T-563). Shard timings use one completion boundary (T-618), and so do restored runs (T-564). `artifact.create` waits up to 120 s for a large folder and never publishes twice (T-576).
- **Hub load and hygiene.** The hub prepares each SQLite statement once and caches it, which cut statement preparation by about 30 % under a session burst (T-768). A healthy hub no longer logs "lease recovery deferred" every 10 minutes (T-820). The legacy spend ledger in `~/.cland` can be retired with `cland executor retire-legacy --confirm-registered-hubs` once every registered hub runs the new state directory; the old file is kept in place (T-794). `cland doctor` finds headless Neovim fixtures and stub hubs whose worktree is gone and ends them, while a real hub of a deleted project is still reported as an orphan hub (T-807, T-965). Fixture receipts are read asynchronously (T-972), and a fixture that cannot write its receipt, as in a read-only QA run, still starts and is treated as not owned (T-974). The doctor's probe runner waits for a timed-out child to close (T-552).
- **Credentials and test isolation.** Account attach commands no longer carry environment values on the command line, and a fake-credential regression proves it; `docs/executor-argv-audit.md` lists every place argv is built from the environment (T-942, for T-492 C3). Every shared test fixture runs with its own HOME, XDG and Git config, a fixed synthetic Git identity, and credentials filtered after every overlay. Deliberate fake providers are typed and refuse anything that isn't a sentinel (T-961, T-964).
- **Test tooling.** `cland qa lint <brief>` checks a QA brief's commands, flags, roles, check ids and cleanup paths against the build (T-957). `durations.ts refresh --add-only` adds missing baselines without touching allowances, and a duration key with no matching test now fails the run (T-956). A T1 test holds every shipped role clause's byte reserve and wording (T-955). A lint refuses `in` on validated dictionaries (T-959). A green `npm run check` prints counts instead of about 10 MB of lint detail (T-954). The Neovim frame recorder refuses a run that skipped files (T-808).
- **Flaky tests fixed** by waiting on the state they assert or by a fake clock: tracker-load (T-570), territory-lock (T-602), account-limits (T-607), the inbox workload fixtures (T-764), init-next's tier boundary (T-804), session-archive affinity (T-757) and the Neovim render-cost ratio (T-963).
- **Docs.** The four rule clusters adopted as guidance are in `docs/agents/tests.md` and `hub/README.md` (T-960). The version is 0.1.5 (T-967).
